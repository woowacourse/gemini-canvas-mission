# gemini-canvas-mission

Gemini Canvas 미션 결과물을 관리하는 저장소입니다.

## 목적

- Gemini Canvas로 제작한 웹앱 결과물을 기록하고 공유합니다.
- 앱별 요구사항, 배포 링크, 회고를 일관된 형식으로 남깁니다.

## 1. 🥕 번개중고당근 (유틸리티)

> "너무 싸게 팔았나?" 하는 후회는 이제 그만! AI 기반 중고가 산출 서비스

배포 링크: [바로가기](https://gemini.google.com/share/2982520471e4)

### 핵심 기능

- AI 시세 분석: Gemini가 상품 이미지를 인식하여 상태를 파악하고 감가상각을 적용한 최적가 제안.
- 판매글 자동 생성: 구매 욕구를 자극하는 매력적인 판매 문구를 자동으로 작성.

### 사용 시나리오

당근마켓이나 번개장터에 물건을 올리기 직전, 적정 가격인지 최종 확인할 때.

## 2. ⚪ 느슨해진 알까기판에 긴장감을 줘 (게임)

> 실력 차이도 운으로 극복한다! 변수가 가득한 예측 불허 알까기

배포 링크: [바로가기](https://gemini.google.com/share/53898c44fbb0)

### 핵심 기능

- 환경 변수 시스템: 매 턴 변하는 풍향/풍속과 지면 높낮이가 알의 궤적에 영향.
- 손떨림 효과: 미세 진동 인터페이스를 통해 조작 난이도 조절.

### 사용 시나리오

친구와 내기를 할 때, 실력 차이에 상관없이 스릴 넘치는 '시간 순삭' 게임이 필요할 때.

## 3. 💻 Kotlin 고차 함수 퀴즈 (학습)

> 지루한 문법 공부는 끝, 퀴즈로 마스터하는 코틀린 고차 함수

배포 링크: [바로가기](https://gemini.google.com/share/30bb5817a97c)

### 핵심 기능

- 실전 코드 퀴즈: map, filter, fold 등 핵심 함수 활용 사례 문제 풀이.
- 성적 피드백: 결과에 따라 '비기너'부터 '장인'까지 등급 부여.

### 사용 시나리오

등하교 길이나 자투리 시간에 가볍게 코틀린 감각을 유지하고 싶을 때.

## 4. ✍️ 리뷰 딸깍 (페어 프롬프트 릴레이)

> "리뷰 쓰기 귀찮으시죠?" 사진 한 장으로 끝내는 고퀄리티 리뷰 생성기

### 페어

- 호이
- 바드

배포 링크: [바로가기](https://gemini.google.com/share/0c591b8f4810)

### 핵심 기능

    - 사장님도 좋아하고 나도 편한 자연스러운 문구 작성.

### 사용 시나리오

배달 음식이나 방문지 리뷰 이벤트에 참여하고 싶은데 문장 쓰기가 고민될 때.

## 📝 AI 사용 일지: 번개중고당근

### 1. 초기 프롬프트

```text
최악이야. 서비스명을 번개중고당근으로 변경해줘. 로고도 번개, 중고, 당근의 개념이 모두 섞인 이미지였으면 좋겠어.
```

- 상황: 자동 생성된 이름인 "가치얼마"나 AI가 추천한 "시세탐정 얼마각"이 마음에 들지 않아서 앱의 이름과 로고만을 변경하고 싶었던 상황

### 2. 프롬프트 개선 과정

위 프롬프트는 제 의도와 달리 로고, 이름을 포함한 앱의 전체 디자인 전체를 바꿔 버리는 문제가 있었습니다. 이를 해결하기 위해 다음과 같은 프롬프트를 사용했습니다.

#### 1차 수정

- 깔끔한 디자인을 위해 UI 스타일을 고정

```text
이름이 화려한건 좋은데 버튼이나 기본적인 UI는 깔끔하게 해줘 주황색(#EF8200)으로
```

위 프롬프트는 UI는 깔끔하게 만들었지만 마음에 들었던 로고에 문제가 생겼습니다.

#### 2차 수정

- 문제가 생긴 로고를 수정

```text
로고는 어디갔어 로고만큼은 당근 + 번개 + 중고

이 세가지가 섞인 재밌는 로고로해줘
```

2차 수정을 통해 로고를 다시 만들었지만 이름의 색상이 마음에 들지 않았습니다!!

#### 3차 수정

- 이름의 단어별 색상을 지정하고 변경 범위를 지정

```text
다른건 변경하지 말고 이름만 변경해

이름에서 번개의 색상은 빨간색(번개 장터 색상)
중고의 색상은 초록색(네이버 색상)
당근의 색상은 #EF8200으로 변경해
```

### 3. 효과적이었던 프롬프팅 전략

- "이름 추천해줘" 같은 모호한 요청보다 원하는 브랜드 명칭과 색상 값을 정확히 전달할 때 원하는 결과가 나왔습니다.
- "다른건 변경하지 말고 ~만"이라는 표현을 사용해 다른 기능에 변화가 없도록 했습니다.

### 4. 배운 점

- 수정 사항의 범위를 명확하게 확정지어 주는 것이 예상치 못한 변경을 막는 좋은 방법이라는 생각이 들었습니다.
