## 이 앱을 만든 이유

### 어떤 문제/불편함을 해결하려고 했나요?

- 중요한 내용을 메모해두고도 다시 확인해야 할 시점을 잊어버려 결국 실천하지 못하는 **건망증 문제**를 해결하고자 했습니다.
- 메모 작성 시마다 일일이 '할 일'인지 '단순 기록'인지 분류하거나 알람 시간을 고민하는 **번거로움**을 줄이고자 했습니다.

### 이 앱을 언제, 어떻게 사용할 건가요?

- 기억해야 할 아이디어나 일정이 생기면 즉시 앱에 기록합니다.
- AI 버튼을 통해 메모의 성격과 적절한 확인 시점을 추천받고, 브라우저가 활성화된 상태에서 정해진 시간에 알림을 받아 내용을 복기합니다.

---

## 주요 기능

- **실시간 인앱 알람:** 브라우저 탭이 열려 있는 동안 리마인드 시간이 되면 전체 화면 모달 팝업으로 알림을 제공합니다.
- **모바일 푸시 알림 연동:** Pushover API를 통해 브라우저를 띄워둔 상태에서 스마트폰으로 실제 푸시 알림을 전송합니다.
- **통합 상태 관리:** '할 일'과 '기록'을 탭별로 필터링하여 관리하며, 완료 시 취소선 효과와 함께 알림 계획을 즉시 중단합니다.
- **자동 알람 취소:** 할 일을 완료 처리하면 예약된 알림이 자동으로 비활성화되어 중복 알림을 방지합니다.

---

## AI 기능

- **문맥 기반 리마인드 시점 추천:** 메모 내용을 분석하여 시간 정보를 추출하거나, 내용의 중요도에 따라 가장 적절한 알람 시각을 제안합니다.
- **콘텐츠 자동 분류:** 작성된 텍스트의 어조와 내용을 파악하여 실행이 필요한 '할 일(Task)'인지 보관용 '기록(Memo)'인지 판단하여 자동으로 속성을 부여합니다.
- **분석 근거 제시:** AI가 왜 해당 시간에 알림을 설정했는지, 왜 그렇게 분류했는지에 대한 이유를 함께 설명하여 사용자의 이해를 돕습니다.

## AI 사용 일지

### 1. 초기 프롬프트

> "게임을 만드려고 하는데 제목은 우아한테크코스 픽셀즈야. 우리 우테코는 건물 11층 12층 13층을 사용중이야. 픽셀즈 게임으로 11층부터 1라운드 13층이 최종라운드로 다 이기면 수료를 할 수 있는 게임을 만들어줘. 이 층마다 맵은 내가 이미지를 첨부할게. 내 이미지를 참고해서 잘 만들어줘."
>
> *(첨부파일: 11층, 12층, 13층 도면 이미지 3장)*

### 2. 프롬프트 개선 과정

#### 처음 결과물의 문제점은 무엇이었나요?

초기에는 '픽셀즈(팩맨)' 특유의 아케이드 요소 없이 단순히 특정 방에 가면 다이얼로그 창이 뜨는 형태였습니다. 벽을 통과할 수 있었고, 라운드 전환 버그도 있었습니다. 또한, 캐릭터 크기 대비 통로가 좁아 진입이 불가능하거나, 랜덤으로 생성된 별이 벽 안쪽이나 데드존(엘리베이터 내부, 공조실)에 생성되어 게임 클리어가 불가능해지는 '소프트락' 문제들이 연이어 발생했습니다. 기술 스택 측면에서도 원했던 순수 HTML/JS가 아닌 React로 작성되어 수정이 필요했습니다.

#### 어떤 식으로 프롬프트를 수정했나요?

- **컨셉/스택 명확화:** "너 픽셀즈 안 해봤어? 별을 다 먹으면 미션 성공이고 괴물이 쫓아오게 해줘", "React 쓰지 말고 HTML/CSS/JavaScript만으로 구현해 줘"와 같이 핵심 메커니즘과 기술 스택을 명확히 재지시했습니다.
- **레벨 디자인 및 버그 리포트 (가장 많은 비중):** "12층 코워킹 존으로 진입이 안 돼 (길이 좁음)", "들어갈 수 없는 곳에 별이 생겨 (데드존)", "토성과 천왕성, 금성과 지구도 못 들어가 (문이 막힘)" 등 테스트 중 발견한 물리적/논리적 오류들을 구체적인 장소와 현상을 짚어가며 수정을 요청했습니다.

#### 몇 번의 반복을 거쳤나요?

총 **10회 이상**의 긴밀한 상호작용(Iteration)을 거쳤습니다.

> 팩맨 룰 적용 → 벽 충돌 구현 → 엘리베이터 이동 버그 수정 → 통로 넓이 조정 → Vanilla JS로 마이그레이션 → 화면 잘림/크기 CSS 수정 → 별 랜덤 스폰 구현 → 별 데드존 생성 버그 수정 → 다중 문(Multi-door) 방 진입 버그 수정

### 3. 효과적이었던 프롬프팅 전략

#### 원하는 결과가 나온 방식

- **직관적 예시와 원인 지목:** "들어갈 수 없는 곳에 별이 생기면 안 돼", "11층 토성에 들어갈 수 없잖아"처럼 버그가 발생한 정확한 위치(Context)를 제공했을 때 AI가 해당 좌표계 배열만 빠르게 뜯어고칠 수 있었습니다.
- **단계적 요구:** 처음부터 완벽한 맵을 짜달라고 하기보다, 일단 벽을 세우고 → 별을 랜덤으로 바꾸고 → 예외 구역을 설정하는 식으로 기능을 하나씩 추가해 나간 것이 코드가 꼬이지 않고 안정적으로 빌드업된 비결이었습니다.

#### 효과가 없었던 방식

- **추상적인 이미지 해석 요구:** 처음에 "내 이미지를 참고해서 만들어줘"라고만 했을 때는 AI가 도면의 물리적 구조(벽, 통로)를 맵 데이터로 자동 변환하지 못했습니다. AI에게 2D 도면을 주더라도 "선을 플레이어가 통과할 수 없는 두께 6px짜리 충돌 벽으로 구현해"라고 프로그래밍 관점에서 지시해야 함을 깨달았습니다.

### 4. 배운 점

AI는 뼈대 코드와 수학적 로직(충돌 판정, 몬스터 추적 로직 등)을 작성하는 데는 천재적이지만, 인간의 눈으로 보는 **레벨 디자인**(통로가 좁아서 캐릭터가 걸리는지, 데드존이 있는지)의 디테일은 완벽하게 잡아내지 못합니다. 따라서 AI가 짜준 코드를 플레이그라운드에서 직접 움직여 보며 **QA(품질 보증) 테스터의 마인드**로 구체적인 피드백을 던져야 완벽한 결과물을 얻을 수 있습니다.
