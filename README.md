# gemini-canvas-mission

Gemini Canvas 미션 결과물을 관리하는 저장소입니다.

## 목적

- Gemini Canvas로 제작한 웹앱 결과물을 기록하고 공유합니다.
- 앱별 요구사항, 배포 링크, 회고를 일관된 형식으로 남깁니다.

## 💻 1. 유틸리티 앱

### 앱 이름
Git 전략 가이드

### 배포 링크
https://gemini.google.com/share/f6d159413371

### 이 앱을 만든 이유

#### - 어떤 문제/불편함을 해결하려고 했나요?

Git을 사용하다 보면 divergent branches, non-fast-forward, CONFLICT 같은 메시지를 마주하지만,
정확히 왜 발생했는지, 그리고 merge를 해야 하는지 rebase를 해야 하는지 즉각 판단하기 어렵습니다.
특히 협업 환경에서는 잘못된 reset --hard나 push --force로 인해 팀 히스토리를 망가뜨릴 위험도 존재합니다.

이 앱은 사용자의 목표(히스토리 유지/정리/동기화)와 현재 상태(로컬 커밋 존재 여부, 보호 브랜치 여부 등)를 기반으로
가장 안전한 전략을 추천하고, “왜 이 전략이 안전한지”까지 설명해주는 의사결정 가이드 역할을 합니다.

또한 단순 문자열 매칭이 아닌 Gemini AI 기반 에러 분석 기능을 추가하여
다양한 Git 에러 상황을 더 유연하게 진단할 수 있도록 확장했습니다.

#### - 본인이 이 앱을 언제, 어떻게 사용할 건가요?

  저는 실제 개발 중 콘솔에서 에러 메시지를 복사해 앱의 “에러 진단” 섹션에 붙여넣고,
추천 전략과 안전 설명을 참고하여 의사결정을 내릴 것입니다.

  특히 협업 상황에서 “이 방법이 왜 안전한가?”를 빠르게 설명할 때 유용하게 사용할 계획입니다.

### 주요 기능

#### - 기능 1: 목표 기반 Git 전략 추천 시스템

사용자가 원하는 목표(로컬 유지, 원격 맞춤, 히스토리 정리, 협업 안전 등)를 선택
현재 상태(로컬 커밋 여부, 보호 브랜치 여부 등)를 체크

조건 기반 로직으로: 권장 전략 (merge / rebase / reset / revert 등), 실행 명령어 세트, 전략 선택 이유, 위험 경고(⚠️ 히스토리 변경 여부 등), 명령어 복사 기능 제공

#### - 기능 2: Git 에러 메시지 진단 시스템

콘솔 에러 메시지 붙여넣기, 기본 문자열 매칭 기반 1차 진단, 상황 설명 + 발생 원인 + 권장 전략 + 실행 명령어 출력

### AI 기능

#### - 어떤 AI 기능을 추가했나요?

Git 에러 메시지 진단 기능에 Gemini AI 분석 기능을 추가했습니다.
사용자가 붙여넣은 에러 로그를 AI가 분석하여:

  - 현재 Git 상태 추정
  - 발생 원인 요약
  - 가능한 해결 전략 비교
  - 안전한 명령어 제안
  - 협업 환경에서의 주의사항 설명

을 자연어 기반으로 생성합니다.

#### - AI 기능이 앱에서 어떤 역할을 하나요?

기존의 단순 패턴 매칭은 미리 정의된 에러에만 대응할 수 있었지만,
Gemini AI를 통해:

 - 예외적인 에러 메시지
 - 복합적인 로그 출력
 - 여러 단계에서 발생한 충돌 로그
 - 사용자의 자유 형식 설명이 섞인 입력

까지도 유연하게 해석할 수 있게 되었습니다.

  - 맵 곳곳에 존재하는 “코드 아이템” 획득 시 포인트 증가
  - 플레이 시간 실시간 측정
  - 최종 점수 = 획득 포인트 + 시간 보너스
  - localStorage 기반 상위 5개 랭킹 저장
  - 엔딩 화면에서 총 시간, 포인트, 최종 점수, 랭킹 출력

## 📚 3. 학습 앱

### 앱 이름
Spring 요청 흐름 시뮬레이터

### 배포 링크
https://gemini.google.com/share/9d159a41fbc1

### 이 앱을 만든 이유

#### - 어떤 문제/불편함을 해결하려고 했나요?

Spring이 아직 익숙하지 않아, HTTP 요청이 들어온 이후

request → controller → service → repository → response까지의 다양한 흐름이<br>
머릿속에 명확하게 그려지지 않는 문제가 있었습니다.

특히,
- DispatcherServlet이 정확히 어떤 역할을 하는지
- Filter와 Controller의 실행 순서
- Validation과 ExceptionHandler는 언제 동작하는지
- 트랜잭션이 언제 시작되고 언제 롤백되는지

를 코드로만 학습할 때는 흐름이 단절적으로 느껴졌습니다.

그래서 단순히 글로 이해하는 것이 아니라,
요청 흐름을 시각적으로 단계별로 확인할 수 있는 시뮬레이터를 만들어
전체 구조를 한 번에 이해할 수 있도록 하고자 이 앱을 제작했습니다.

#### - 본인이 이 앱을 언제, 어떻게 사용할 건가요?
- Spring 구조가 헷갈릴 때
- 예외 처리 흐름을 복습할 때
- 트랜잭션 롤백 시점을 확인하고 싶을 때
- 멘토링이나 설명 상황에서 “흐름을 시각적으로 보여주고 싶을 때”

실제 개발 중 “이 에러는 어디서 발생한 거지?”라는 의문이 생기면,
해당 상황을 시뮬레이터에 설정해보면서 흐름을 다시 점검하는 용도로 활용할 계획입니다.

### 주요 기능

#### - 기능 1: 단계별 요청 흐름 시각화

- Client → Filter → DispatcherServlet → Controller → Service → Repository → DB → Response

- 각 단계가 순차적으로 강조되며 실행 흐름 표시

- 특정 단계에서 예외 발생 시 ExceptionHandler로 분기

- 트랜잭션 상태 (ACTIVE / COMMITTED / ROLLED_BACK) 시각화

이를 통해 정상 흐름과 예외 흐름의 차이를 한눈에 확인할 수 있습니다.

#### - 기능 2: 시나리오 기반 분기 시뮬레이션

- Validation 실패 (400)
- 인증 실패 (401)
- 비즈니스 예외 (409)
- DB 예외 (500)

등 다양한 상황을 체크박스로 선택하면 해당 위치에서 예외가 발생하고 응답이 어떻게 반환되는지 확인할 수 있습니다.

각 단계는 클릭 시 설명, 핵심 개념, 코드 예시까지 함께 제공합니다.

### 이 앱을 만든 이유

#### - 어떤 문제/불편함을 해결하려고 했나요?
일정 시간마다 Driver/Navigator 역할을 바꾸자는 약속을 해도
집중하다 보면 자연스럽게 흐지부지되는 경우가 많았습니다.

그래서
- 역할 전환을 명확하게 관리하고
- 현재 목표와 진행 상황을 기록하며
- 막힌 지점을 구조적으로 정리할 수 있는 도구

가 필요하다고 느껴 이 앱을 제작하게 되었습니다.

#### - 본인이 이 앱을 언제, 어떻게 사용할 건가요?
- 우테코 미션을 페어와 함께 진행할 때
- 분 단위 집중 세션을 운영할 때

세션 시작 시 목표와 완료 기준을 입력하고,
타이머를 켜서 일정 시간마다 역할을 전환하며 진행합니다.

### 주요 기능

#### 기능 1: Driver/Navigator 전환 타이머

- 일정 시간마다 역할 전환 알림
- 현재 역할 시각적 표시
- 세션 시간 실시간 카운트

이를 통해 자연스럽게 역할 균형을 유지할 수 있습니다.

#### 기능 2: 1분 전 알림
1분 전 TTS로 생성한 알림을 통해서 마무리할 시간을 알려줍니다.

### AI 기능

#### - 어떤 AI 기능을 추가했나요?

  타이머 종료 1분 전에 Gemini TTS API를 사용하여 "역할 교체 1분 전입니다"라는 음성 안내가 나오도록 기능을 추가했습니다.

#### - AI 기능이 앱에서 어떤 역할을 하나요?

이 기능은 브라우저의 기본 음성이 아닌 고품질의 Gemini AI 음성을 생성하여 재생하며, 지시사항에 따라 PCM 데이터를 WAV로 변환하여 재생하는 로직을 포함하고 있습니다.

### 2. 프롬프트 개선 과정

- 처음 결과물의 문제점은 무엇이었나요?

점수 산정 시스템이나, 명칭, 플레이어나 배경 등 디테일한 요소들이 아쉬웠습니다.

- 어떤 식으로 프롬프트를 수정했나요?

구체적으로 어느 부분이 마음에 안들고 어떤 방향으로 수정해줬으면 좋겠는지 작은 부분들을 지시했습니다.
변경하려는 방향에 대해서 확실히 인지하고 지시해야 원하는 방향으로 수정해줬기 때문에 좀 더 수치화적이고, 자세한 묘사를 활용해서 지시했습니다. 

- 몇 번의 반복을 거쳤나요?

20번 이상의 반복을 거쳤습니다.

### 3. 효과적이었던 프롬프팅 전략

- 어떤 방식으로 요청했을 때 원하는 결과가 나왔나요?

구체적인 수치나 사진을 첨부하여 원하는 컨셉을 전달해주는게 효과적이었습니다.

- 반대로 효과가 없었던 방식은 어떤게 있었나요?

두루뭉실하게 얘기하면 오히려 수정해야할 부분들이 많이 늘어나고 기존의 부분들도 수정되어서 되돌려야하는 경우가 있었습니다.

### 4. 배운 점

- Gemini Canvas를 효과적으로 사용하기 위한 나만의 팁이 있다면?

원하는 것에 대해서 확실한 기획이 필요합니다. 수정해야할 부분을 확실히 지정하여 프롬프트를 작성하면 완성도 높은 서비스를 만들 수 있을 것 같습니다.
