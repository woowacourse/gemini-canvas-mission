## 앱 이름: 프로젝트 회고 보드
## 카테고리: 페어 프롬프트 릴레이

### 배포 링크
https://gemini.google.com/share/68a782cf664b

### 이 앱을 만든 이유
**어떤 문제/불편함을 해결하려고 했나요?**
- 미션/프로젝트마다 회고를 작성하는게 어려울 때도, 잊어버릴 때도 있습니다.
- KPT기법을 활용하여 간단하게 회고를 작성하며, 공유할 수 있는 앱을 만들고 싶었습니다.

**이 앱을 언제, 어떻게 사용할 건가요?**
- 회고가 필요할 때 언제든, KPT기법에 따라 회고를 작성합니다.
- 다른 사람의 회고도 참고하며, 서로의 느낀점을 공유합니다.

### 주요 기능
- 로그인 기능
- 태그 매칭 기능
- 회고 비교 기능
- 태그를 통한 AI통합 회고 분석 기능

### AI 기능 (해당되는 경우)

**어떤 AI 기능을 추가했나요?**
- 여러 개의 회고를 요약정리해주는 기능

**AI 기능이 앱에서 어떤 역할을 하나요?**
- 같은 태그의 회고글 요약 결과를 표출해줍니다.
- 회고에 사용된 핵심 키워드들을 보기 쉽게 인포그래픽으로 표시해줍니다.

## AI 사용 일지

### 1. 초기 프롬프트
- 단체의 구성원들이 함꼐 활용하는 게시판 형식의 웹앱 생성해줘.
  같은 활동을 하고 회고를 남길거고 
서로의 회고를 공유하고 비교분석하고 상호작용할 수 있어야 해.
  HTML, CSS, JS로만 한정한다.

### 2. 프롬프트 개선 과정
- 처음 결과물의 문제점은 무엇이었나요?
  - 정말 간단한 게시판 형식이 나와서 문제였습니다. 생각보다 심플해서 추가해야할 기능이 많았던 것 같습니다.
- 어떤 식으로 프롬프트를 수정했나요?
  - 4~5개의 기능들을 처리해달라고 요청하다, 막히는 순간이 있으면 1~2개의 요청을 보냈습니다.
  - 기능 수정 요청과 UI 수정 요청을 병합하여 보내다가 점점 기능 수정 요청 위주로만 요청, 기능 구현 마무리 후
  UI 수정 요청으로 방향을 잡았습니다.
- 몇 번의 반복을 거쳤나요?
  - 총 31번의 프롬프트를 보냈습니다.

### 3. 효과적이었던 프롬프팅 전략
- 어떤 방식으로 요청했을 때 원하는 결과가 나왔나요?
  - 핵심적인 기능만 요청하고, 부연설명이 없을 때 생각보다 만족스러운 결과가 나오는 경우가 많았던 것 같습니다.
- 반대로 효과가 없었던 방식은 무엇이었나요?
  - 오히려 잘 모르는 부분에 대해서 애매한 키워드를 이용해 요청하는게 AI가 최적의 기술을 선택하는데 방해가 되었던 것 같습니다.
