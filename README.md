# gemini-canvas-mission

Gemini Canvas 미션 결과물을 관리하는 저장소입니다.

## 목적

- Gemini Canvas로 제작한 웹앱 결과물을 기록하고 공유합니다.
- 앱별 요구사항, 배포 링크, 회고를 일관된 형식으로 남깁니다.

## 앱 이름: GENGA TALK
### 카테고리: 페어 프롬프트 릴레이

### 배포 링크
https://gemini.google.com/share/77bec98248d5

### 이 앱을 만든 이유
- 어떤 문제/불편함을 해결하려고 했나요?
  - 우아한테크코스에서 처음 만난 사람들과 스몰토크를 할 때의 막막함과 어색함을 해결하고 싶었습니다.
  - 사람들이 보통 게임을 하며 자연스럽게 친해진다는 점에 시작하여 긴장감 넘치는 '젠가' 게임과 '스몰토크'를 결합한 인터랙티브 앱을 만들었습니다.
- 이 앱을 언제, 어떻게 사용할 건가요?
  - 새로운 팀이 결성되었을 때, 아이스브레이킹 세션에서 활용합니다.
  - 오프라인 모임에서 스마트폰이나 노트북을 가운데 두고 한 명씩 돌아가며 젠가를 뽑고, 화면에 나오는 질문에 답변하며 서로에 대한 정보를 자연스럽게 습득합니다.

### 주요 기능
- 3D 젠가 타워: 실제 젠가와 유사한 물리적 구조를 구현했습니다. 층마다 방향이 교차되는 정밀한 스택 로직이 적용되어 있습니다.
- 8가지 고정 테마 + 커스텀 주제: 일상, 취향, 개발, 가치관 등 8가지 프리셋 테마뿐만 아니라 사용자가 원하는 어떤 주제(TMI, 첫사랑 등)든 입력하여 시작할 수 있습니다.
- 타이밍 게이지 시스템: 단순 클릭이 아니라 0~100 사이를 왕복하는 게이지를 '그린존'에 맞춰 멈춰야 하는 핑퐁 게임 요소를 넣어 긴장감을 더했습니다.

### AI 기능 (해당되는 경우)
- 어떤 AI 기능을 추가했나요?
  - 콘텐츠 사전 로딩: 게임 시작 시 선택한 주제에 맞는 스몰토크 질문 30개와 전용 벌칙 1개를 즉석에서 생성합니다.
  - 맥락 인지 질문 생성: 사용자가 입력한 커스텀 주제를 분석하여 해당 상황에 가장 적절하고 재미있는 질문을 짧고 간결하게 뽑아냅니다.
  - 매너 벌칙 큐레이션: 처음 만난 사이임을 고려하여 무례하지 않으면서도 분위기를 띄울 수 있는 '귀여운 미션' 위주로 벌칙을 생성합니다.

- AI 기능이 앱에서 어떤 역할을 하나요?
  - 무한한 확장성: 질문을 하드코딩하지 않기 때문에 매 판마다 새로운 대화 주제를 만날 수 있어 재플레이 가치가 높습니다.
  - 게임의 흐름 유지: 30개의 질문을 한 번에 미리 생성해두는 로직을 통해, 게임 도중 네트워크 지연 없이 매끄러운 사용자 경험(UX)을 제공합니다.  
  - 사회적 윤활제: 자칫 딱딱해질 수 있는 분위기를 AI가 생성한 '참신한 질문'과 '무해한 벌칙'을 통해 부드럽게 만들어주는 '아이스브레이킹 전문가' 역할을 수행합니다.

## AI 사용 일지

### 1. 초기 프롬프트
```aiexclude
처음 만난 사람들끼리 스몰토크할 주제를 추천해주는 게임을 만들고 싶어(javascript, html, css만 사용)

처음 화면에서 주제를 정하면, 그 다음 화면에서 주제에 맞는 스몰토크할 질문들을 젠가 게임으로 만들거야. 
젠가는 3D로 구현되어 있고, 각자 한 턴씩 돌아가면서 젠가를 뽑고 해당 질문에 대답을 하면서 서로 알아가는 거지
만약 젠가가 무너지면 그 사람이 벌칙을 수행해야 해. 벌칙은 니가 랜덤으로 정해주되 처음 만난 사람들끼리도 충분히 수행할 수 있을 법한 난이도로 해줘(ex) 커피 쏘기, 짐 가방 들기 등)
```

### 2. 프롬프트 개선 과정
- 처음 결과물의 문제점은 무엇이었나요?
  - 구체적이지 않고 추상적으로 요청했기 때문에 제가 원하는 방향대로 구현되지 않았습니다. 예를 들어 저는 주제가 최소 9개 이상 생성되기를 원했지만, 실제로는 4개 정도만 하드코딩되어 고정되는 상황이 발생했습니다. 또한, 좀 더 다양한 질문을 접하고 싶었는데 질문들 역시 모두 하드코딩되어 확장성이 부족했습니다.
- 어떤 식으로 프롬프트를 수정했나요?
  - 보다 구체적으로 지시하도록 프롬프트를 수정했습니다. 먼저, 고정 주제의 개수를 명확히 지정했고, 고정된 주제 중 마음에 드는 것이 없을 경우 사용자가 키워드를 입력하면 AI가 해당 키워드에 맞는 질문을 생성하여 젠가 블록과 매칭하도록 요청했습니다. 또한, 게임을 새로 시작할 때마다 질문과 벌칙이 매번 다르게 생성되도록 수정하여 반복 플레이의 재미를 높였습니다.
- 몇 번의 반복을 거쳤나요?
  - 16회

### 3. 효과적이었던 프롬프팅 전략
- 어떤 방식으로 요청했을 때 원하는 결과가 나왔나요?
  - 구체적으로 명시해주었을 때 가장 원하는 결과가 잘 나왔습니다
- 반대로 효과가 없었던 방식은 무엇이었나요?
  - 기본 뼈대를 만들고 조금씩 수정하는 방식은 처음에는 효과가 있었습니다.
    그러나 반복 횟수가 많아질수록 초기 뼈대 구조를 잊고, 전체 코드를 다시 작성해버리는 경우가 종종 발생했습니다.

### 4. 배운 점
- Gemini Canvas를 효과적으로 사용하기 위한 나만의 팁이 있다면?
  - 기능을 추상적으로 명세하지 말고 최대한 구체적으로 원하는 방향을 말하거나 최소한 변경되면 안 되는 요소나 금지 조건은 함께 명시하는 것이 좋을 것 같습니다
  - 모든 기능을 AI에게 한 번에 맡기지 말고, 기본 뼈대를 설계할 때 기본적인 객체 정보와 객체의 상태, 행위 정도는 명시해주는 것이 좋을 것 같습니다.
  초기에는 코드 구조를 이해하기 쉬웠지만, 기능이 점점 추가되면서 구조가 복잡해졌고, AI의 수정이 의도와 다르게 이루어질 경우 직접 수정하기가 매우 어려워졌습니다.
  따라서 처음에는 구체적으로 세세하게 뼈대를 작성해주고 그 틀 안에서 AI를 활용할 수 있도록 하는 것이 좋을 것 같습니다

### 5. 리뷰어에게 피드백 받고 싶은 포인트
- AI에게 여러 번 수정을 요청할 경우, 수정을 원하지 않았던 기존 프롬프트를 모두 잊고 다시 새롭게 코드를 작성하는 경우가 종종 발생했었습니다.
  리뷰어님들은 보통 이럴 때 어떻게 해결하셨나요?
- 기능이 점점 많아질수록 코드가 길어지고 복잡해지는데, 이럴 때 AI에게 어떤 단위로 수정을 요청하는 것이 가장 효율적인지 궁금합니다.
  예를 들어 전체 파일을 기준으로 수정 요청을 하는 게 좋은지, 아니면 특정 함수나 컴포넌트 단위로 잘라서 요청하는 게 좋은지 알고 싶습니다.
- 리뷰어님들은 보통 설계 단계에서 AI를 어느 정도까지 활용하시는지도 궁금합니다.
