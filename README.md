## 📝 AI 사용 일지 
대상 앱 이름: LinkMind AI (스마트 URL 아카이빙 서비스) </br>
#### 1. 초기 프롬프트
```
# Summary
실리콘밸리 프로덕트 오너의 관점에서 URL 아카이빙 서비스의 핵심 기능과 AI 통합 전략을 기획합니다. 정보 과부하 시대의 사용자 페인 포인트를 해결하고, 직관적인 링크 관리 및 AI 기반 추천 기능을 통해 사용자의 생산성을 극대화하는 무료 서비스 개발을 위한 상세 로드맵을 제시합니다.

# Role
당신은 실리콘밸리에서 15년 이상 성공적인 SaaS(Software as a Service) 제품을 기획하고 런칭해온 베테랑 프로덕트 오너(PO)이자 소프트웨어 아키텍트입니다. (이하 생략 - 지식 노동자 문제 해결, 서비스 비전, 페르소나, 핵심 기능 상세, AI 통합, 제약 조건 등 마크다운으로 구조화된 상세 명세서 제공)

# Instruction
1. 서비스 비전 및 핵심 가치 정의
2. 핵심 기능 상세 정의 및 사용자 경험 설계
3. Gemini AI 통합 상세 설계
4. 기술 및 아키텍처 고려사항 (HTML, CSS, JavaScript만으로 개발)
5. 개발 로드맵 (MVP)
```
#### 2. 프롬프트 개선 과정

- 초기 결과물의 문제점:첫 프롬프트로 훌륭한 UI와 기본적인 MVP 뼈대(바닐라 JS)를 얻어냈으나, 일부 버그와 AI 할루시네이션이 발생했습니다.
- UI 버그: iframe 캔버스 환경의 보안 정책으로 인해 브라우저 기본 알림창(confirm, prompt)이 차단되어 폴더 추가/삭제 기능이 먹통이 되는 현상이 있었습니다.
- 기능적 문제 : 유튜브 링크 입력 시, AI가 URL 문자열만 보고 영상 내용을 상상해서 매번 다르게 지어내는 환각 현상이 발생했습니다.
- 프롬프트 수정 방식:에러 로그 기반 디버깅: "삭제 기능 안 됨"이라는 모호한 요청 대신, 발생한 [CONSOLE_ERROR]와 스택 트레이스를 그대로 복사해서 프롬프트에 제공하여 근본 원인을 파악하게 했습니다.
- 할루시네이션 해결 방향 전환 (Prompt Engineering :arrow_right: RAG 방식): AI에게 "지어내지 마라"라고 지시어만 강제하는 방식이 실패하자, "CORS 프록시를 통해 HTML 메타데이터(제목, 설명, 작성자, 썸네일)를 먼저 스크래핑한 뒤, 그 텍스트만 프롬프트의 컨텍스트로 주입하여 요약하게 하라"고 구현 방식의 수정을 요청하였습니다.
- 반복 횟수: 초기 뼈대 생성 이후, 버그 픽스, 에러 핸들링, 할루시네이션 제어, 기능 추가(댓글 분석, 썸네일) 및 롤백 등 약 12~13회의 반복적인 티키타카(Iteration)를 거쳤습니다.
  
#### 3. 효과적이었던 프롬프팅 전략

- 효과적이었던 방식: </br>
1. 명확한 역할(Role)과 구조화된 지시: 첫 프롬프트에서 '실리콘밸리 PO'라는 페르소나와 함께 마크다운으로 요구사항을 세밀하게 분리한 덕분에, 코딩 지식이 깊지 않아도 기획 의도에 완벽히 부합하는 세련된 UI와 기능 명세가 단번에 도출되었습니다.
2. 콘솔 에러 메시지 원문 제공: 자바스크립트나 API 연동 오류가 났을 때, 현상을 설명하기보다 에러 로그 전체를 그대로 복붙해 주었을 때 AI가 원인(JSON 파싱 오류, API 파라미터 충돌 등)을 훨씬 빠르고 정확하게 진단하고 코드를 수정했습니다.
3. 데이터를 직접 쥐어주는 방식 (Context Injection): AI가 외부 링크를 스스로 파악하도록 내버려 두지 않고, "HTML을 먼저 읽어서 데이터를 추출한 뒤 그 데이터로만 대답해라"라고 데이터 플로우를 통제하여 할루시네이션을 줄일 수 있었습니다.

- 효과가 없었던 방식 : </br>
1. 단순한 행동 금지 지시: "내용을 상상해서 지어내지 마", "정확한 내용만 써"라고 프롬프트로만 압박했을 때, AI는 정보가 부족하면 답변 자체를 포기해버려 에러(응답 데이터 없음)를 뱉거나 지시를 무시하고 계속 부정확한 답변을 하였습니다.
2. 구체적이지 않은 버그 리포팅: 단순히 "삭제 기능 여전히 안 됨"이라고 여러 번 말했을 때는 AI가 변수 타입 변환(String(id)) 같은 표면적인 코드만 계속 수정하며 헤맸습니다. 실행 환경(iframe)의 특성 등 구체적인 상황을 인지시켜야 근본적인 UI 개선(커스텀 모달 제작)으로 넘어갈 수 있었습니다.
