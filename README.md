# gemini-canvas-mission

Gemini Canvas 미션 결과물을 관리하는 저장소입니다.

## 앱 이름: 슬랙 테마 생성기

## 카테고리: 유틸리티 앱

### 배포 링크

https://gemini.google.com/share/de3bad94f6f3

### 이 앱을 만든 이유

- 슬랙 테마를 바꾸고 싶은데 코드 4개를 직접 조합하는 게 불편했고, 결과를 적용 전에 미리 볼 수 없어서 답답했습니다.
- 이미지 하나로 테마를 뚝딱 만들고 싶을 때, 또는 슬랙 테마 코드를 공유받아서 미리 확인할 때 사용합니다.

### 주요 기능

- 슬랙 사이드바 실시간 미리보기 (색상 변경이 즉시 반영)
- 색상 피커로 4개 색상(시스템 탐색/선택 항목/현재 상태/알림) 직접 조정
- 테마 코드 문자열 입력 시 자동 파싱 및 미리보기 반영
- 프리셋 저장 및 불러오기
- 다크 모드 지원

### AI 기능

- 이미지를 드롭하면 Gemini Vision이 이미지에서 4가지 조화로운 색상을 추출해 슬랙 테마로 자동 생성합니다.
- AI가 단순 색상 추출이 아닌 슬랙 UI에 어울리는 조화로운 팔레트를 구성합니다.

## 앱 이름: AI와 끝말잇기 대결

## 카테고리: 게임

### 배포 링크

https://gemini.google.com/share/c25465c6fea2

### 이 앱을 만든 이유

- 끝말잇기는 혼자 하기 심심하고 같이 할 사람도 없을 때가 많습니다.
- AI가 심판 + 상대방 역할을 동시에 해줘서 언제든지 혼자 즐길 수 있고, 단어 공부도 됩니다.

### 주요 기능

- 플레이어 ↔ AI 턴제 끝말잇기
- 두음법칙 자동 처리 (예: 낙→락 허용)
- 이미 사용한 단어 중복 방지
- AI 힌트 받기 (막힐 때 도움 요청 가능)
- 기권하기 및 게임 재시작

### AI 기능

- Gemini가 AI 심판 역할로 입력한 단어가 실제 표준국어대사전에 있는 명사인지 검증하고 뜻을 알려줍니다.
- Gemini가 AI 상대방 역할로 끝말잇기 규칙에 맞는 다음 단어를 실시간으로 생성합니다.
- 힌트 요청 시에도 Gemini가 플레이어에게 유효한 단어를 추천합니다.

https://gemini.google.com/share/99cd6475cb30

- 워크플로우를 눈으로 보면서 에이전트 개념을 직관적으로 익힐 수 있는 인터랙티브 시각화 도구가 필요했습니다.

### 주요 기능

- **Workflow Simulator**: 자연어 명령어를 입력하면 AI 에이전트의 추론 → 도구 선택 → 실행 → 결과 반환 과정을 단계별로 시각화
- **MCP Playground**: Host / MCP Client / MCP Server 간의 통신 흐름을 레고 조립하듯 구성하고 애니메이션으로 확인
- 추천 프롬프트로 빠른 체험 가능
- 일시정지/재개 기능으로 학습 속도 조절

### AI 기능

- AI 기능 없이 순수 시뮬레이션으로 구현된 학습용 앱입니다.
- 실제 AI 에이전트 아키텍처(Tool Call, Reasoning, Result)를 시각적으로 모사합니다.

### 배포 링크

https://gemini.google.com/share/abed78383010

### 이 앱을 만든 이유

- 여행지를 고르지 못하고 무한 고민하는 사람들을 위해 지구본에 다트를 던져 랜덤으로 여행지를 정해주는 앱입니다.
- 어디로 여행할지 고민될 때, 또는 색다른 여행지를 발견하고 싶을 때 사용합니다.

- 여행지 명소 3곳 및 여행 꿀팁 표시

### AI 기능

- Imagen AI가 해당 여행지의 시네마틱 풍경 사진을 실시간으로 생성합니다.

## AI 사용 일지

> 가장 잘 만들어진 앱: **AI 세계 여행 다트**

### 1. 초기 프롬프트

```
여행지를 정하는 웹앱 서비스를 만들고 싶다.

기본형태가 지구본(위성형태)이 매우 빠르게 회전상태

클릭을 하면 클릭한 위치에 포인트가 남는다 (다트 형식도 가능)

그 포인트를 서서히 3초 뒤에 확대되면서 자세한 정보 및 관람을 추천하는 형태를 가짐

단, "HTML, CSS, JavaScript만 사용해서 만들어줘. React나 다른 프레임워크는 사용하지 마."
```

### 2. 프롬프트 개선 과정

- **처음 결과물의 문제점**:
  - 다시 던지기 버튼을 눌렀을 때 지구본이 처음 위치로 돌아오지 않음
  - 지구본에서 찍은 좌표와 AI 분석에 사용된 좌표가 달랐음 (클릭한 화면 위치가 아닌 실제 지표면 좌표를 써야 했음)
  - 경도 수치가 실제 위치와 크게 차이남 (호주를 찍었는데 전혀 다른 좌표가 나옴: 실제 `-33.04, 148.81` → 앱 `-29.86, 57.16`)

- **프롬프트 수정 과정** (총 10회):
  1. 다시 던지기 시 지구본 위치 초기화 요청
  2. 클릭 좌표를 화면 좌표가 아닌 지구본 실제 좌표로 계산하도록 수정 요청
  3. 경도 오차 원인 분석 요청 → Gemini가 UV Mapping 기준점 문제임을 설명
  4. 경도 보정 로직 수정 (`Math.atan2(vec.z, -vec.x)` 적용)
  5. 직접 코드 수정 제안: `Math.atan2(-vec.z, vec.x)` 로 변경 요청
  6. 장소 이미지 1장 추가 요청 (Imagen 4.0 연동)
  7. 지구본 사이즈를 80%로 축소 요청 (위아래가 잘리는 문제)
  8. 회전 속도 stepper 추가 (0.5x~2.0x → 이후 0.1x~2.0x로 재수정)
  9. 카메라 시점 옵션 추가 (북반구/적도/남반구)
  10. UI 정리: 컨트롤들을 우측 상단으로 이동, 버튼 텍스트 줄바꿈 방지, 중앙 안내 문구 고정 위치 설정

### 3. 효과적이었던 프롬프팅 전략

- **효과적이었던 방식**: 버그를 설명할 때 실제 수치를 함께 제시하는 것이 효과적이었습니다. "좌표가 틀려"보다 "내가 찍은 곳은 `-33.04, 148.81`인데 앱에서는 `-29.86, 57.16`이 나와"처럼 구체적인 값을 주니 Gemini가 문제의 방향을 잡을 수 있었습니다. 다만 Gemini가 제시한 원인 분석(UV Mapping 기준점 오프셋)은 부분적으로만 맞았고, 실제로는 지구본 회전 상태를 제거하는 `worldToLocal` 변환과 Three.js 좌표계에서 텍스처가 감기는 방향에 맞춰 `atan2` 인자의 부호를 교정하는 복합적인 문제였습니다.
- **효과적이었던 방식 2**: AI의 수정안이 완벽하지 않을 때, 코드 수준에서 직접 대안을 제안하는 것이 효과적이었습니다. Gemini가 제안한 `Math.atan2(vec.z, -vec.x)`로는 경도 기준점과 측정 방향이 모두 어긋났는데, 직접 `Math.atan2(-vec.z, vec.x)`로 수정을 제안하니 정확히 반영됐습니다. AI 응답을 그대로 따르기보다 원리를 이해하고 검증하는 과정이 중요했습니다.
- **효과 없었던 방식**: "경도가 좀 차이나는 것 같다" 같은 막연한 표현은 부정확한 보정을 반복하게 만들었습니다. 구체적인 수치 없이 감으로 설명하면 Gemini도 감으로 대응합니다.

### 4. 배운 점

- **버그 리포트는 수치로**: 추상적인 설명보다 실제 입력값과 기대값, 실제 출력값을 함께 제시하면 훨씬 빠르게 해결됩니다.
- **기능은 하나씩 추가**: 초기 프롬프트에서 핵심 기능(지구본 + 클릭 + AI 정보)만 요청하고, 이미지 생성/속도 조절/시점 옵션은 따로따로 추가했습니다. 한 번에 몰아서 요청했다면 누락이 많았을 겁니다.
- **Gemini가 모른다고 해도 직접 시도해보기**: 경도 계산 로직은 Gemini가 제안한 수식이 맞지 않아서 제가 직접 대안 수식을 제시했고, 그게 맞았습니다. AI 응답을 무조건 따르기보다 직접 검증하고 수정안을 제안하는 것도 중요합니다.

### 5. 리뷰어에게 피드백 받고 싶은 포인트

- Imagen으로 생성한 이미지는 실제 장소를 검색해보면 분위기는 비슷하지만 결국 AI가 만든 가상 이미지입니다. 여행지 추천이라는 도메인 특성상 실제 사진이 더 적합할 것 같은데, 실제 이미지를 가져오는 방법을 잘 모르겠어서 피드백 받고 싶습니다.
