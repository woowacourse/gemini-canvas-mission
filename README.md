# gemini-canvas-mission

Gemini Canvas 미션 결과물을 관리하는 저장소입니다.

## 목적

- Gemini Canvas로 제작한 웹앱 결과물을 기록하고 공유합니다.
- 앱별 요구사항, 배포 링크, 회고를 일관된 형식으로 남깁니다.

## AI 사용 일지

### 1. 초기 프롬프트
```
[페르소나]
지금 일본어 학습을 하기 위한 우테코 학생이다.
개발 공부를 하다가 너무 질려서 일본어 공부가 하고 싶었고,
기초가 부족해서 기초부터 학습을 하려고 한다.

[목표]
학습을 하고자 하는 목표는 아래와 같다.

1. 일본어 기초 글자 학습 (히라가나/카타가나)
- 히라가나와 카타가나는 연속해서 같은 글자가 출제되면 안된다.
- 문제는 버튼형 객관식으로 4개의 정답 중 하나만 선택한다.
- 각 객관식은 영어로 발음을 표현해서 나타낸다.

2. 문장 스피치 학습 (히라가나 또는 카타가나로 구성된 문장, 한자는 없어야 함)
- 문장은 5문장으로 구성된다.
- 문장은 Google AI API를 활용해서 5문장을 가져온다.
- 음성 인식은 Web Speach API를 활용한다.

3. 문장 받아쓰기 학습 (2번과 동일)
- 문장을 가져오는 것은 2번과 동일하다.
- Google AI TTS를 활용해서 문장을 읽어준다.
- 읽기 버튼을 추가한다.

[기술 스택]
HTML, CSS, JavaScript(Vanila)만 활용
```

### 2. 프롬프트 개선 과정

- 처음 결과물의 문제점은 무엇이었나요?
  - 사용자 발음 비교 시 마침표(.)로 인해 발음이 같더라도 오답으로 처리되는 오류가 발생했습니다.
  - 일본어 문장 듣고 받아쓰기할 때 TTS 재생 오류가 발생했습니다.
- 어떤 식으로 프롬프트를 수정했나요?
  - 문제점 단락과 수정 요구사항 단락을 구분하여 문제점을 작성하고 뒤에 어떤식으로 수정하면 좋을지 작성했습니다.

    ```
    [문제점]
    스피치 결과 비교 시 마침표(.)로 인해 동일 발음임에도 틀린 결과가 출력되는 오류 발생
    일본어 문장 듣고 받아쓰기 시 TTS 오류 발생
    
    [개선점]
    - 일본어 받아쓰기 탭 내 일본어 키패드 추가
    - 문자 학습 UI 개선 (정답과 오답의 배경색 구분)
    - 히라가나 받아쓰기와 가타카나 받아쓰기 탭 분리
    ```

- 몇 번의 반복을 거쳤나요?
  - 15번의 수정을 거쳐서 결과물을 완성했습니다.

### 3. 효과적이었던 프롬프팅 전략

- 어떤 방식으로 요청했을 때 원하는 결과가 나왔나요?
  - 사용 대상, 목표, 문제점, 개선 사항 등 현재 상태와 기대하는 결과를 상세히 설명했을 때, 의도에 가장 가까운 결과물이 나왔습니다.
- 반대로 효과가 없었던 방식은 무엇이었나요?
  - `이거 안 되는데 수정해 줘`, `제목 색 바꿔 줘`와 같이 구체적이지 않고 추상적인 요청은 원치 않는 결과가 나오는 경우가 많았습니다.

### 4. 배운 점

- Gemini Canvas를 효과적으로 사용하기 위한 나만의 팁이 있다면?
  - 사용 대상, 목표 기능, 원하는 결과, 문제점, 수정 요구 사항 등을 단락별로 나누어 프롬프트를 작성하면 비교적 완성도 높은 결과물을 얻을 수 있습니다.
