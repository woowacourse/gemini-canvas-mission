## 🎶 앱 이름: Muchive Studio (뮤카이브스튜디오)
## 🛠️ 카테고리: 유틸리티 앱

### 🔗 배포 링크
- [배포 링크](https://gemini.google.com/share/394d27827782)

### 🧠 이 앱을 만든 이유
- 음악 스트리밍 서비스의 플레이리스트는 단순히 목록으로만 존재하여, 특정 곡에 대한 간단한 느낌이나 한줄평을 기록하거나 얽힌 개인적인 추억이나 감상을 시각적으로 소장한다는 느낌을 받기 어렵습니다.
- 또한, 수많은 곡 사이에서 당시의 무드에 맞는 곡을 **'상자'에서 꺼내 보는 듯한 아날로그적 경험**을 디지털로 구현하고자 했습니다.

### ✨ 주요 기능
- **3D Isometric 인터페이스**: 곡들이 담긴 레코드 박스를 3D로 구현하여 시각적 즐거움을 제공합니다.
- **iTunes API 실시간 연동**: 곡 제목이나 아티스트 검색만으로 고화질 앨범 커버와 정확한 곡 정보를 불러옵니다.
- **동적 라벨(Label) 시스템**: 왼쪽 사이드바에서 나만의 라벨을 자유롭게 추가하고 삭제하며 컬렉션을 관리할 수 있습니다.
- **한줄평 기록 및 수정**: 각 곡에 대한 나만의 메모를 남기고, 상세 보기 모달에서 언제든 수정하거나 기록을 파기할 수 있습니다.
- **사용자 편의성(UX)**: ESC 키를 통한 뒤로가기 동작과 실시간 텍스트 검색 기능을 지원합니다.

## 🧱 앱 이름: 서바이벌 테트리스
## 🎮 카테고리: 게임

### 🔗 배포 링크
- [배포 링크](https://gemini.google.com/share/58c97a024ee4)

### 🧠 이 앱을 만든 이유
- 단순히 블록을 쌓기만 하는 전통적인 테트리스 방식에서 벗어나, 플레이어가 직접 게임판 내부의 캐릭터가 되어 생존해야 하는 액션 요소를 결합하고자 했습니다.
- **'블록을 어디에 쌓을 것인가'**라는 전략적 고민과 **'떨어지는 블록을 어떻게 피할 것인가'**라는 순발력이 동시에 요구되는 독특한 게임 경험을 제공합니다.
- 내가 직접 쌓은 블록들이 거대한 벽이 되어 다가오는 공포와, 그 사이를 누비며 살아남는 긴박함을 **1인칭 시점**을 통해 극대화했습니다.

### ✨ 주요 기능
- **듀얼 시점 시스템 (Tab)**: 전지적 작가 시점의 **'테트리스 모드(2D)'**와 캐릭터의 눈으로 세상을 보는 **'생존 모드(3d, 1인칭)'**를 실시간으로 전환할 수 있습니다.
- **실시간 압사 및 리스폰 로직**: 떨어지는 블록에 깔릴 경우 목숨을 잃으며, 현재 위치에서 가장 높은 안전 지대로 즉시 리스폰되어 게임을 중단 없이 이어갈 수 있습니다.
- **스마트폰 UI 미니맵**: 1인칭 모드 시 우측 하단에 나타나는 스마트폰 화면을 통해 전체 맵 상황과 자신의 위치를 실시간 이미지 텍스처로 확인할 수 있습니다.
- **정교한 물리 엔진**: 점프 높이 제한(2칸), 천장 충돌 판정, 카메라 클리핑(벽 뚫기) 방지 등 쾌적한 1인칭 플레이를 위한 디테일한 물리 처리가 포함되어 있습니다.
- **내장 효과음 시스템**: Web Audio API를 활용하여 블록 안착, 라인 클리어, 점프, 발걸음, 데미지 등의 효과음을 별도 파일 없이 구현했습니다.

## 🕵️ 앱 이름: Trace: 런타임 수사대
## 📚 카테고리: 학습 앱

### 🔗 배포 링크
- [배포 링크](https://gemini.google.com/share/59845e0cf9a7)

### 🧠 이 앱을 만든 이유
- 단순한 오타부터 복잡한 로직 결함까지 실무에서 자주 발생하는 버그 시나리오를 게임 형식으로 학습하여 디버깅 능력을 키우고자 했습니다.
- 사이버펑크 UI와 긴장감 넘치는 사운드 효과를 통해 지루할 수 있는 코드 리뷰 과정을 박진감 넘치는 수사 과정으로 탈바꿈시켰습니다.

### ✨ 주요 기능
- HTML, CSS, JavaScript, React의 핵심 문법 및 로직 결함을 수사할 수 있습니다.
- **4단계 난이도 시스템**
  - **Lv1(입문)**: 단순 철자 오류 및 오타 수사
  - **Lv2(숙련)**: 문법 표준 위반 및 구문 결함 교정
  - **Lv3(전문)**: 알고리즘 로직 및 시맨틱 태그 오용 수사
  - **Lv4(마스터)**: 비동기 병목, React 렌더링 최적화, 불변성 위반 등 고급 결함 제압
- 총 **160개**의 방대한 문제 데이터베이스에서 매 수사마다 **5개의 사건을 랜덤 추출**하여 매번 새로운 플레이 경험을 제공합니다.
- 별도의 창 없이 코드 라인을 클릭하여 즉시 수정하고 검증(Verify)할 수 있습니다.
- 난이도가 높은 사건(Lv3 이상)의 경우, 해결의 실마리를 제공하는 힌트 기능을 사용할 수 있습니다.
- 제한 시간 내 해결 여부에 따라 보너스 점수를 차등 부여하여 경쟁 요소를 더했습니다.

### 🤖 AI 기능 (해당되는 경우)
- Gemini 모델을 활용하여 실제 개발 현장에서 발생하는 수많은 안티 패턴과 오류 사례들을 분석하고, 이를 게임에 적합한 **160개의 고품질 수사 데이터**로 가공했습니다.
- **정답 정규화 로직**: 유저가 입력한 다양한 형태의 정답을 AI적 사고로 분석하여, 공백이나 탭의 차이가 있더라도 코드의 의미가 정답과 일치하는지 판단합니다.

## 🪐 앱 이름: 행성이메이커
## 🧩 카테고리: 페어 프롬프트 릴레이

### 🔗 배포 링크
- [배포 링크](https://gemini.google.com/share/8af457a78ea9)

### 🧠 이 앱을 만든 이유
- 우테코의 캐릭터인 **행성이**를 사용하고 싶지만, 원하는 행동을 하고 있는 행성이가 없어서 포기할 때가 많았습니다.  
  그래서 **상황에 따라 필요한 행성이를 AI가 학습을 통해 만들어주는 서비스**를 제작하였습니다.

### ✨ 주요 기능
- **상황별 이미지 생성**: 사용자가 입력한 텍스트 상황에 맞춰 **3가지 버전**의 행성이 이미지를 동시에 생성합니다.
- **개발자 전용 랜덤 생성**: **'개발자 랜덤 행성이 만들기'** 버튼을 통해 버그 수정, 코드 리뷰, 배포 성공 등 개발자라면 누구나 공감할 만한 상황을 **랜덤으로 추천**받아 즉시 생성할 수 있습니다.
- **일관된 캐릭터 스타일 유지**: 레퍼런스 이미지와 정교한 프롬프트 설계를 통해 낙서 형태의 원형 몸통, 두꺼운 선, 무표정한 점눈, 고리, 팔다리 등 **'행성이'만의 고유한 정체성**을 일관되게 유지합니다.

### 🤖 AI 기능
- **사용된 모델**: `gemini-2.5-flash-image-preview` (나노 바나나)
- **AI의 역할**
  - **멀티모달 이미지 생성**: 텍스트 프롬프트뿐만 아니라 업로드된 레퍼런스 이미지를 함께 분석하여 행성이의 화풍(손그림 스타일, 흑백 선화)을 완벽하게 복제합니다.
  - **스타일 가이드 준수**: `"머리와 몸통 구분 없음"`, `"고리는 필수"`, `"눈은 항상 점 2개"`와 같은 복잡한 캐릭터 구조 규칙을 이해하고, 사용자가 어떤 상황을 입력하더라도 해당 규칙 안에서 창의적인 결과물을 도출합니다.

### 📝 1. 초기 프롬프트
> "첨부한 행성이 이미지를 바탕으로 새로운 행성이 이미지를 생성하는 웹 앱을 만들거야. 원하는 형태의 행성이를 사용자가 텍스트로 입력하면 3가지의 행성이 이미지를 AI를 사용하여 생성할거야. 각 이미지 아래 다운로드 버튼이 있고 해당 버튼을 누르면 이미지를 다운로드 받도록 만들어줘."

### 🔧 2. 프롬프트 개선 과정
- **처음 결과물의 문제점**
  - AI가 이미지에 임의의 영문 텍스트나 말풍선을 넣었습니다.
  - 행성이의 얼굴에 입이 없거나 눈이 3개가 되는 등 신체 구조적 오류가 잦았습니다.
  - 또한 머리와 몸통을 분리하여 사람처럼 그리는 경향이 있었습니다.
- **수정 방향**
  1. `'Negative Prompt'` 성격의 제약 조건(**NO text, NO bubbles**)을 강화했습니다.
  2. `'Appearance Rules'` 섹션을 만들어 `"머리와 몸통 구분 없는 단일 구체"`, `"눈 2개, 입 1개 고정"` 등의 물리적 규칙을 명문화했습니다.
  3. 선의 질감을 `"찌그러진 손그림(wobbly, jittery)"`으로 묘사하여 인위적인 완벽함을 제거했습니다.
- **반복 횟수**
  - 약 **8회**의 세부 조정을 거쳐 현재의 일관된 스타일을 완성했습니다.

### 🎯 3. 효과적이었던 프롬프팅 전략
- **성공적이었던 방식**
  - 레퍼런스 이미지를 직접 입력(Multi-modal)으로 주면서, 텍스트 프롬프트에서  
    `"Reference Image의 스타일을 강력하게 고수하라"`는 문구를 **대문자로 강조**했을 때 가장 결과가 좋았습니다.
  - 또한 신체 부위의 개수를 **`EXACTLY TWO`** 와 같이 **수치로 명시**하는 것이 효과적이었습니다.
- **효과가 없었던 방식**
  - 단순히 `"귀엽게 그려줘"`, `"낙서처럼 그려줘"` 같은 추상적인 묘사는 AI마다 해석이 달라 결과물이 들쭉날쭉했습니다.

### 🧩 4. 배운 점
- Gemini Canvas를 사용하면 코드 수정과 프롬프트 실험을 실시간 Preview로 즉시 확인할 수 있어, 대규모 이미지 생성 로직을 최적화하는 데 매우 효율적이라는 것을 배웠습니다.  
  특히 복잡한 CSS 레이아웃과 비동기 API 통신 로직을 한 번에 관리하기에 최적입니다.
