CSR vs SSR 렌더링 시각화

클라이언트 사이드 렌더링(CSR)과 서버 사이드 렌더링(SSR)이 브라우저에서 어떻게 동작하는지 비교해 보세요.
FCP(화면 표시)와 TTI(상호작용 가능) 시점의 차이에 주목하세요!

CSR

0ms

빈 HTML을 먼저 받고, 브라우저가 JS를 실행하여 화면을 그립니다.

FCP (화면 표시)
-
TTI (상호작용)
-
https://myapp.com/csr
빈 화면 (HTML 도착)
이미지

프론트엔드 개발 가이드

CSR은 처음에 비어있지만, 한 번 로드되면 깜빡임 없이 부드러운 페이지 이동이 가능합니다.

좋아요를 눌렀습니다!
렌더링 타임라인
  • 🌐 브라우저, 서버에 페이지 요청
  • 📄 빈 HTML 수신 (JS 링크 포함)
  • ⚡ JS 번들 다운로드 및 파싱
  • 🚀 렌더링 완료 (FCP & TTI 동시 달성)

SSR

0ms

서버에서 완성된 HTML을 보내주어 화면은 빨리 보이지만, JS 로드 전까진 반응하지 않습니다.

FCP (화면 표시)
-
TTI (상호작용)
-
https://myapp.com/ssr
요청 대기 중...
이미지

프론트엔드 개발 가이드

SSR은 화면이 빠르게 나타나 사용자 경험이 좋고, SEO(검색엔진 최적화)에 유리합니다.

렌더링 타임라인
  • 🌐 브라우저 요청 & 서버에서 HTML 렌더링
  • 📄 완성된 HTML 수신 및 화면 표시 (FCP)
  • ⚡ JS 번들 다운로드 및 실행 완료
  • 🚀 Hydration 완료 (TTI 달성)
