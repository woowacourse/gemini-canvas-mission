# gemini-canvas-mission

Gemini Canvas 미션 결과물을 관리하는 저장소입니다.

## 목적

- Gemini Canvas로 제작한 웹앱 결과물을 기록하고 공유합니다.
- 앱별 요구사항, 배포 링크, 회고를 일관된 형식으로 남깁니다.

## ✅ 제출 체크리스트

- [x] 4개 웹앱 제출 (유틸리티 앱 1개 + 게임 1개 + 학습 앱 1개 + 페어 프롬프트 릴레이 1개)
- [x] 최소 1개 앱에 Gemini AI 기능 포함
- [x] 모든 앱이 배포 링크로 정상 동작함
- [x] AI 사용 일지 작성 완료

### 2. 프롬프트 개선 과정

- 처음 결과물의 문제점은 무엇이었나요?
  - 첨부한 이미지를 결과물인 웹앱에 사용할 수 없었음
  - 지시한 이미지 생성 규칙을 무시하는 문제
  - 이미지 생성 모델을 직접 지정하지 않아 상대적으로 성능이 떨어지는 이미지 모델을 사용하는 문제
- 어떤 식으로 프롬프트를 수정했나요?
  - 첨부할 이미지를 별도로 호스팅하여 링크로 전달하고 결과물에 반영하도록 프롬포트로 지시하였음
  - 다시 한번 규칙을 지시하면서 이미지 생성에 사용될 프롬포트에 강조 표현을 사용하도록 프롬포팅하였음
  - 구체적으로 Nano Banana를 사용하여 이미지를 생성하도록 지시하였음
- 몇 번의 반복을 거쳤나요?
  - 전달한 이미지와 구체적으로 지시한 이미지 생성 모델은 한번에 바로 적용되었음
  - 이미지 생성 규칙은 6번 정도 지시하여 원하는 결과물을 얻었음

### 3. 효과적이었던 프롬프팅 전략

- 어떤 방식으로 요청했을 때 원하는 결과가 나왔나요?
  - 이미지 생성 규칙(스타일)에 대해서는 '강력하게 고수하도록' 같은 강조 표현을 사용하고, 지속적으로 생성된 이미지를 확인하며 '외곽선 두께를 110%로'와 같이 세세하게 지시할 수록 원하는 결과물에 가까워졌음
- 반대로 효과가 없었던 방식은 어떤게 있었나요?
  - '눈코입은 점 3개로 이루어져있어'와 같은 모호한 표현은 눈을 3개로 그리고 입을 별도로 그리는등 등의 문제를 야기했음

### 4. 배운 점

- Gemini Canvas를 효과적으로 사용하기 위한 나만의 팁이 있다면?
  - 이미지 첨부는 별도로 호스팅하여 링크로 전달하기
  - 이미지 생성 기능을 넣을 경우 이미지 생성 모델로 Nano Banana를 사용하도록 지시하기
  - 이미지 생성시 이미지 생성 프롬포트에 대해서는 최대한 세세하고 모호하지 않으며 강조 표현을 사용하여 규칙이 누락되지 않도록 하기
  - Gemini Canvas 배포 링크는 iframe로 한번 감싸져있고 iframe에 지정된 url이 매번 새롭게 변경되므로 로컬 스토리지나 클립보드 API를 정상적으로 사용할 수 없다는 점 인지하기
