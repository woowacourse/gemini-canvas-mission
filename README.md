# 1. 유틸리티 앱

## 앱 이름: DevUtils

## 카테고리: 유틸리티 앱

### 배포 링크

https://gemini.google.com/share/8a5c8057aee6

### 이 앱을 만든 이유

- 어떤 문제/불편함을 해결하려고 했나요?
  : 평소 개발을 하면서 저는 마크다운 문법을 사용하는 노션과 같은 도구를 자주 사용하고, 프로젝트의 할 일을 관리하는 도구 또한 자주 사용합니다. 두 도구를 왔다갔다 하는 번거로움을 줄이기 위해 마크다운 기록과 할 일 관리 서비스를 통합하여 유용하게 사용할 수 있도록 의도하였습니다.

- 이 앱을 언제, 어떻게 사용할 건가요?
  : 우테코에서 팀 프로젝트를 진행할 때, 프로젝트의 제가 맡은 부분을 여러 섹션으로 나누고 그 섹션에 맞게 여러 할 일을 정리할 것이며 할 일을 체크하며 완료해나가면서 섹션에 해당하는 내용으로 개발 일지를 작성할 것입니다.

### 주요 기능

- 홈 대시보드
  : 깃허브 스타일의 최근 한 달 간의 활동 잔디 그래프, 전체 통계, 오늘/내일 마감인 할 일 모아보기 기능을 제공합니다.
- 개발 일지
  : 마크다운 파서를 통해 실시간으로 렌더링되는 에디터를 지원하여 개발 일지를 작성할 수 있습니다. 작성한 일지들은 수정이나 삭제가 자유롭고, 그리드 형태의 카드로 보관되며 제목 검색 및 6개 단위의 페이지네이션 기능을 제공합니다.
- 할 일 관리
  : 스프린트나 기능별로 '섹션'을 나누고 하위에 할 일을 추가할 수 있으며, 할 일은 마감일을 설정할 수 있습니다. 전체 진행도를 프로그래스 바로 보여주며, 섹션 검색 기능 및 4개 단위 페이지네이션, 섹션 아코디언 UI 기능을 제공합니다.

# 2. 게임

## 앱 이름: 궁국의 꼬치 달인

## 카테고리: 게임

### 배포 링크

https://gemini.google.com/share/3546a72e0549

### 이 앱을 만든 이유

- 어떤 문제/불편함을 해결하려고 했나요?
  : 현대인의 바쁜 삶에서 로딩이 길고 복잡해서 이해하기 어려운 게임 대신에, 빠르고 쉽게 즐길 수 있는 B급 감성의 게임을 목표로 제작하였습니다.
- 이 앱을 언제, 어떻게 사용할 건가요?
  : 출퇴근길 지하철이나 버스 안, 기다리는 시간, 화장실에 있는 시간 등 자투리 시간에 주로 사용합니다. 복잡한 조작 없이 오직 마우스나 손가락만 사용해 화면을 좌우로 드래그하는 것만으로 간단하게 플레이할 수 있습니다.

### 주요 기능

- 60초 타임어택 플레이: 60초라는 제한 시간 동안 최대한 많은 꼬치를 레시피대로 정확하게 완성해야 합니다.

- 점진적 난이도 조절 & 스마트 레시피 시스템: 플레이어의 점수가 높아질수록 요구하는 꼬치의 길이가 길어집니다. 특히, 무작위로 레시피를 생성할 때 막대 밖으로 재료가 삐져나가지 않도록 스마트하게 레시피의 재료들의 개수를 조율합니다.

- 슬라이딩 연출: 떨어지는 재료가 꼬치 끝부분에 닿으면, 허공을 건너뛰지 않고 꼬치 막대를 타고 주르륵 미끄러져 내려가는 애니메이션을 연출했습니다.

- 테트리스형 주머니 생성 시스템: 특정 재료만 연속으로 나오거나 안 나오는 답답한 상황을 방지하기 위해, 6가지 재료가 담긴 주머니에서 재료를 뽑는 알고리즘을 적용하여 모든 재료가 공평하게 떨어지도록 설계했습니다.

- 게임 편의성 제공: [ESC] 키를 통한 일시정지 기능, 게임 시작 시 3초 카운트다운, 그리고 세션 내의 최고 점수를 기록하는 기능을 제공합니다.

# 3. 학습 앱

## 앱 이름: Flexbox Cafe

## 카테고리: 학습 앱

### 배포 링크

https://gemini.google.com/share/1f83db6a08d4

### 이 앱을 만든 이유

- 어떤 문제/불편함을 해결하려고 했나요?
  : 프론트엔드 입문자들이 CSS Flexbox의 다양한 속성(justify-content, align-items, flex-wrap, gap 등)을 글로만 배우면 헷갈리고 금방 잊어버리는 문제를 해결하고자 했습니다. 눈대중으로 레이아웃을 맞추는 잘못된 습관을 고치고, 브라우저가 요소를 렌더링하는 정확한 좌표와 수치(px, rem, vh 등) 개념을 게임을 통해 직관적으로 학습할 수 있도록 시각적인 피드백이 즉각적으로 주어지는 환경이 필요했습니다.
- 이 앱을 언제, 어떻게 사용할 건가요?
  : CSS 레이아웃 개념을 처음 배우거나, 실무 중에 Flexbox 속성이 헷갈릴 때 가볍게 몸풀기용으로 사용합니다. 왼쪽 에디터 창에 CSS 코드를 입력하여 햄버거, 커피, 케이크 등의 요소를 손님이 원하는 정확한 타겟 위치로 이동시키며 학습합니다.

### 주요 기능

- 실시간 레이아웃 렌더링 및 정밀 판별 시스템: 입력한 CSS가 즉시 화면에 반영되며, 정답 제출 시 픽셀 단위(5px 오차 허용)로 실제 요소들의 렌더링 좌표를 비교하여 완벽하게 일치해야만 정답으로 인정합니다.

- 문제 은행 시스템: 총 22개의 문제 풀(쉬움, 보통, 어려움)에서 매번 10문제를 무작위로 추출하여, 반복 학습을 해도 지루하지 않게 구성했습니다.

- 개발 친화적 UX/UI: VS Code 테마를 차용한 코드 에디터 디자인을 적용했고, 오답 시 시각적 흔들림 효과, Shift + Enter 단축키 제출 등 개발자에게 익숙하고 편리한 경험을 제공합니다.

- 학습 보조 도구('👀 정답 위치 보기' 버튼): 내 요소와 목표 위치가 겹쳐서 안 보일 때 버튼을 눌러 정답 위치만 확인할 수 있으며, 다시 코딩을 시작하면 자동으로 내 요소가 다시 나타나는 편의 기능을 지원합니다.

- 학습 결과 및 성취도 분석: 10개의 문제를 모두 풀면 '총 제출 횟수'를 기반으로 정답률을 계산하여, 실력에 따른 맞춤형 바리스타 등급(평가 텍스트)을 보여줍니다.

# 4. 페어 프롬프트 릴레이 앱

## 앱 이름: 우아한 할리갈리

## 카테고리: 페어 프롬프트 릴레이

### 배포 링크

https://gemini.google.com/share/867f5f5f90a1

### 이 앱을 만든 이유

- 어떤 문제/불편함을 해결하려고 했나요?

: 오프라인에서 할리갈리 보드게임을 하려면 반드시 실물 카드와 종이 필요하고, 혼자서는 연습하거나 즐기기 어렵다는 한계가 있었습니다. 또한, 게임 중 과일 개수를 순간적으로 계산하고 먼저 종을 쳤는지 판정하는 과정에서 사람의 눈으로 놓치는 경우가 있어 룰 분쟁이 발생하기도 합니다. 이를 웹 어플리케이션으로 디지털화하여 언제 어디서나 정확한 판정으로 게임을 즐길 수 있도록 해결했습니다.

- 이 앱을 언제, 어떻게 사용할 건가요?

: 친구와 물리적인 보드게임 없이 하나의 키보드로 같이 게임을 하고 싶을 때(웹 접속 후 키보드 양옆에 앉아서 플레이), 혼자서 순발력을 기르거나 심심풀이로 AI 봇들과 대결하며 킬링타임을 보내고 싶을 때 사용합니다.

### 주요 기능

- 로컬 멀티플레이 및 혼합 대전 지원: 총 2명부터 최대 5명까지 게임 인원을 설정할 수 있으며, 사람 플레이어(최대 2명)와 AI 봇을 자유롭게 섞어서 게임을 구성할 수 있습니다.

- 사용자 맞춤형 조작 및 UI: 참가자별로 원하는 닉네임(최대 5자)을 설정하고, '카드 젖히기'와 '종 치기' 단축키를 키보드의 원하는 키로 자유롭게 커스텀할 수 있습니다. 현재 턴, 남은 카드 수, 파산 직전(마지막 기회) 경고 등 플레이어의 상태를 한눈에 파악할 수 있는 반응형 정보 카드를 제공합니다.

- 할리갈리 룰 자동 판정 시스템: 바닥에 깔린 모든 플레이어의 카드를 인식하여, 같은 종류의 과일 합이 정확히 5개가 되었을 때만 정답으로 인정합니다. 오답일 경우 다른 모든 생존 플레이어에게 자신의 카드를 1장씩 나눠주는 페널티 시스템과 파산(탈락) 시스템이 완벽히 구현되어 있습니다.

- 세밀한 봇 난이도 조절: 쉬움(느린 봇), 보통(일반 봇), 어려움(우테코 에이스 봇) 3단계로 반응 속도와 실수 확률을 세밀하게 조절하여 사용자의 실력에 맞춰 대결할 수 있습니다.

- 역동적인 애니메이션 효과: 화면 정중앙에서 터지는 듯한 만화적인 말풍선(정산 결과 안내), 종 흔들림 효과, 카드 뒤집기 모션 등을 통해 시각적인 타격감과 재미를 더했습니다.

### AI 기능 (해당되는 경우)

- 어떤 AI 기능을 추가했나요?
  : Google Gemini API를 활용한 'AI 봇 페르소나 자동 생성' 기능을 추가했습니다.
- AI 기능이 앱에서 어떤 역할을 하나요?
  : 사용자가 혼자 봇과 게임을 할 때 자칫 단조로워질 수 있는 점을 보완하기 위해, 게임 시작 버튼을 누르면 AI가 즉석에서 우아한테크코스(개발 부트캠프) 컨셉에 맞는 봇들을 생성합니다. 또한, 단순히 '봇1', '봇2'가 아닌 "프론트노인", "자바의정석"과 같은 5자 이내의 개발자 감성을 가진 닉네임을 사용합니다.

## 📝 AI 사용 일지

### 1. 초기 프롬프트

"개발자를 위한 유틸리티 서비스를 개발하고 싶어. 기능으로는 크게 두 가지가 있는데, 하나는 내가 개발하면서 기록할 것이나 일지처럼 작성하고 싶은 내용을 적을 수 있는 기능이야. 이 기능은 마크다운 문법으로 작성할 수 있고, 내가 작성한 내용이 오른쪽에 마크다운으로 변환된 내용으로 보이는 식이야. 두 번째 기능은 할 일 관리 기능과 비슷한데, 하나의 섹션을 내가 생성할 수 있고 그 섹션 아래의 하위 항목들을 여러 개 두어서 todolist처럼 작동하는거야. 이 기능은 맨 위에 진행도를 확인할 수 있고, 하위항목을 클리어하면 체크박스를 눌러 취소선으로 완료를 확인할 수 있어. 기본적으로 HTML, CSS, JAVASCRIPT, TYPESCRIPT만 사용해주고, 마크다운이나 필요한 경우 추가적인 라이브러리를 사용해줘"

### 2. 프롬프트 개선 과정

#### 2-1. 처음 결과물의 문제점은 무엇이었나요?

- 초기에는 요청에 따라 Tailwind CSS, Marked.js 등의 외부 라이브러리를 CDN으로 불러와 사용했습니다. 하지만 미션 내부적으로 제한이 있기도 하고 단일 파일 구조에서 외부 의존성이 높아지는 것이 부담스러웠고, prompt()나 confirm() 같은 브라우저 기본 알림창이 Canvas 환경 보안 정책상 동작하지 않는 버그가 발생했습니다. 또한, 기능이 추가될수록 데이터가 많아질 때의 UI 처리(스크롤, 가독성)가 부족했습니다.

#### 2-2. 어떤 식으로 프롬프트를 수정했나요?

- 의존성 제거: "라이브러리도 사용하지 말고 순수 HTML, CSS, JavaScript만 사용해서 구현하는 구조로 변경해줘"라고 명시적으로 요구하여 바닐라 환경으로 전환했습니다.

- 구체적인 UI/UX 지시: "인라인 블록에서 타이틀을 설정하게 해줘", "버튼을 회색으로 비활성화해줘", "z-index를 분리해서 본 영역에 영향을 안 주게 해줘" 등 눈에 보이는 화면(UI)과 동작(UX)을 구체적으로 묘사했습니다.

- 단계별 확장: 처음부터 모든 기능을 요구하지 않고, [기본 뼈대] -> [바닐라 마이그레이션] -> [홈 대시보드 추가] -> [페이지네이션 및 검색 추가] -> [잔디 그래프(히트맵) 추가] 순으로 기능을 덧붙여 나갔습니다.

#### 2-3. 몇 번의 반복을 거쳤나요?

- 약 15회 정도의 핑퐁(반복)을 거쳤습니다.

### 3. 효과적이었던 프롬프팅 전략

#### 3-1. 어떤 방식으로 요청했을 때 원하는 결과가 나왔나요?

- 위치와 조건의 명확화: "새로운 섹션 추가하기 버튼은 맨 마지막에 존재하는 섹션 아래에 위치시키고, 페이지네이션 버튼들은 그 아래 배치해줘"처럼 컴포넌트의 DOM 계층구조나 화면상 위치를 정확히 짚어주었을 때 단번에 원하는 레이아웃이 나왔습니다.

- 역제안 요청: "홈 페이지에 넣을 만한 기능 및 디자인이 있을까? 추천해줘"라고 열린 질문을 던졌을 때, AI가 '잔디 그래프(히트맵)'나 '뽀모도로 타이머' 같은 훌륭한 기획 아이디어를 제공해주어 앱의 퀄리티가 크게 높아졌습니다.

#### 3-2. 반대로 효과가 없었던 방식은 무엇이었나요?

- "기능이 작동하지 않는 것 같아"라고만 말했을 때보다, "섹션 삭제가 안 되고, 탭이 안 들어가져"라고 구체적인 증상을 말했을 때 AI가 코드의 어느 부분(HTML 구조 깨짐, 모달 미적용 등)이 문제인지 훨씬 빠르고 정확하게 파악했습니다.

### 4. 배운 점

#### 4-1. Gemini Canvas를 효과적으로 사용하기 위한 나만의 팁이 있다면?

- 바닐라 JS의 활용: 프레임워크 없이도 AI는 정규식을 활용한 마크다운 파서나 복잡한 히트맵 렌더링을 순수 바닐라 JS로 완벽하게 짜낼 수 있습니다.

- 환경적 제약 이해하기: 캔버스(미리보기) 환경에서는 alert, confirm이 막히거나 툴팁이 잘리는(overflow: hidden) 현상이 자주 발생합니다. 이럴 때는 "커스텀 모달로 만들어줘", "툴팁을 fixed 포지션으로 최상단에 띄워줘"라고 물리적인 해결책을 프롬프트에 포함하는 것이 좋은 것 같습니다.

- 데이터 마이그레이션 신경 쓰기: 데이터 구조를 변경할 때(예: 일지를 단순 문자열에서 객체 배열로 변경할 때) 로컬 스토리지에 기존 데이터가 남아있으면 에러가 납니다. AI가 이를 알아서 처리해 주기도 하지만, "기존 데이터와 충돌 안 나게 처리해줘"라고 덧붙이면 더 안전한 것 같습니다.

### 5. 리뷰어에게 피드백 받고 싶은 포인트

- 순수 HTML/JavaScript로 상태 관리(State Management)를 구현했는데, 이 패턴(상태 객체를 만들고 render() 함수로 UI를 업데이트하는 방식)이 효율성 측면이나 가독성 측면에서 괜찮은지 피드백을 받고 싶습니다.

- 사용자의 모니터 크기가 다양할텐데, 대부분의 데스크탑 환경 모두에서 말풍선이나 플레이어 카드 배치가 어색하지 않고 직관적인지 UI/UX 관점의 피드백을 받고 싶습니다.

- 총 15번의 프롬프트를 통해 앱을 완성했는데, 이 과정 중 여러 단계를 하나로 압축하여 더 효율적으로(적은 턴 수로) 지시할 수 있었던 프롬프팅 최적화 포인트가 있는지 궁금합니다.
