# gemini-canvas-mission

Gemini Canvas 미션 결과물을 관리하는 저장소입니다.

## 목적

- Gemini Canvas로 제작한 웹앱 결과물을 기록하고 공유합니다.
- 앱별 요구사항, 배포 링크, 회고를 일관된 형식으로 남깁니다.

---

이 레포지토리는 우아한테크코스 교육 과정 중 겪는 기술적 어려움을 해소하고, 크루 간의 유대감을 높이며, 성장을 가속화하기 위해 제작된 유틸리티 앱들을 포함하고 있습니다.

## 1. 유틸리티 앱

### 앱이름 : **SBD 8-WEEK ELITE: 스트렝스 코치**

### 카테고리 : 유틸리티

### 배포링크 :

https://gemini.google.com/share/931081e26004

### 이앱을 만든이유

- 어떤 문제/불편함을 해결하려고 했나요?
  - "고중량 3대 운동을 목표로 하는 운동인들은 “얼마나 들 수 있느냐”보다 “어떻게, 언제, 얼마나 회복하면서 올려야 하는지”에 더 큰 어려움을 겪습니다.
  - 스트렝스 프로그램은 이미 많이 존재하지만**, 자신의 1RM, 운동 가능 일수, 회복 상태에 맞게 직접 적용하기 어렵고,** 중량·횟수·휴식 시간을 따로 메모하거나 계산해야 하며 수면, 영양, 추가 운동 등 **회복 요소는 관리되지 않은 채 감각에 의존**하는 경우가 많습니다.
  - 그 결과 **과도한 피로 누적, 정체기, 잦은 프로그램 변경**으로 이어집니다.
  - 이 앱은 **“생각은 줄이고, 들어야 할 중량과 쉬어야 할 시간에만 집중할 수 있도록”** 스트렝스 훈련 전반을 하나의 흐름으로 관리하기 위해 만들어졌습니다."
- 이 앱을 언제, 어떻게 사용할 건가요?
  - 이 앱은 8주 단위 스트렝스 사이클을 기준으로 사용합니다.프로그램 시작 전, 현재 3대 운동 1RM과 주당 운동 가능 일수를 입력하면 개인 맞춤형 8주 스트렝스 프로그램이 자동 생성됩니다.
  - 프로그램 사용중 →수면 시간, 단백질·탄수화물 섭취량, 추가 운동 여부를 간단히 기록하고 이를 기반으로 주간 피로도 및 훈련 피드백을 제공합니다.
  - 8주 프로그램 종료 후1RM 측정을 통해 성과를 정리하고, 다음 사이클을 위한 최종 피드백을 제공합니다.
    이 앱은 헬스장에서 바로 열어 확인하는 실전용 스트렝스 보조 도구이자, 3대 500을 향해 가는 과정을 체계적으로 관리하는 개인 코치 역할을 목표로 합니다.

### 주요 기능

1. **1RM 기반 8주 스트렝스 사이클 자동 생성**
   - 스쿼트/벤치/데드 1RM 입력만으로 **주차별 점진적 과부하 중량(kg)** 이 자동 계산되어 표 형태로 제공됩니다.
2. **주간 체크인(Week Check-in)으로 훈련 수행도 기록**
   - W1~W8 헤더 클릭 → 모달에서 **세트 단위 성공/실패(녹색/빨간색)** 를 바로 체크하여 “실패 패턴”을 누적 기록합니다.
3. **3일 루틴(월/수/금) 중심의 미니멀 구성**
   - 복잡한 분할 없이 **핵심 5종목(스쿼트/벤치/데드/OHP/펜들레이 로우)** 만으로 구성된 **실전형 주간 루틴**을 제공합니다.
   - (금요일에는 Heavy 스쿼트 등 강도 포인트를 분리)
4. **회복 데이터(수면·영양·추가 활동) 입력 → 컨디션/피로 지수화**
   - 주차별로 **수면 시간, 단백질(g), 탄수화물(g), 추가 활동(휴식~고강도 보조)** 을 간단 입력하면
     **컨디션 스코어(0~100) + 피로도 바(누적 피로 지수)** 로 시각화합니다.
5. **주간 피드백 제공(영양 가이드 + 강도/피로 피드백)**
   - 입력된 회복 지표와 실패 기록을 기반으로
     **탄수화물 ‘유지/증량’ 가이드**, **수행 안정성(실패 많음/안정적 수행)** 등 주간 코칭 메시지를 제공합니다.
6. **8주 완료 후 ‘심층 분석 리포트’ 자동 생성**
   - 신규 1RM 입력 시 **종목별 증가량/총 SBD 변화량**, **평균 수면·단백질·탄수**, **총 실패 횟수**, **세트 성공률(%)** 을 산출합니다.
7. **실패 패턴 기반 차기 사이클 제언**
   - 실패 누적 정도와 컨디션 지표를 종합해
     **다음 사이클의 빌드업 전략(예: 볼륨 주간 추가, 초기 강도 조정)** 등 “코치 코멘트” 형태의 개선 방향을 제공합니다.

## 2. 게임 앱

### 앱이름 : 짭스트워

### 카테고리 : 게임 앱

### 배포링크

https://gemini.google.com/share/7a5eea92b508

### 이앱을 만든이유

- 어떤 문제/불편함을 해결하려고 했나요?
  - 잠깐 시간이 빌 때 **학습/설명 없이 바로 몰입**해서 즐길 수 있는 *초간단 캐주얼 슈팅*이 필요했습니다.
  - 광고에서 보던 ‘라스트워’ 특유의 **수학 게이트 선택 → 병력 증가 → 탄막 화력 쾌감**을 짧은 플레이로 빠르게 느낄 수 있는 형태로 직접 구현하고자 했습니다.
- 이 앱을 언제, 어떻게 사용할 건가요?
  - 출퇴근/쉬는 시간/대기 시간처럼 **5~10분 붕 뜨는 시간**에 바로 실행합니다.
  - 스테이지/난이도를 선택한 뒤, 중앙 다리 위 전장에서 좌우 이동만으로 **게이트를 선택**하고, 병력을 늘리며 적과 보스를 처치하는 방식으로 플레이합니다.

### 주요 기능

1. **시작 화면 & 스테이지 선택 UI**
   - 시작 화면 → 스테이지 선택 화면으로 이어지는 게임 플로우
   - 스테이지/난이도(Easy·Normal·Hard) 선택 지원
2. **라스트워 스타일 ‘런앤건’ 전투 구조**
   - 자동 전진/자동 사격 + 좌우 이동(드래그/스와이프)만으로 조작
   - 전투 구역을 **가운데 다리(좁은 전장)** 로 제한해 원작 느낌 강화
3. **수학 게이트 시스템(핵심 성장 메커니즘)**
   - / - / × / ÷ 형태의 게이트를 선택 통과
   - 선택 결과가 병력(화력)에 즉시 반영되어 “리스크-리턴” 판단 유도
4. **군집(스쿼드) 시스템**
   - 병력이 늘어날수록 **군집 대형(그리드 포메이션)** 으로 확장
   - 성능을 위해 **최대 200명 제한**(렉 방지)
5. **적군/보스/특수 적(오우거) 등장 및 밸런싱**
   - 일반 적 + 보스가 주기적으로 등장(긴장감 유지)
   - 오우거 타입 등 패턴/체력이 다른 적 추가로 난이도 조절
6. **HP 바 & 데미지 텍스트 연출**
   - 아군/적군 모두 HP를 **바(Bar)** 형태로 직관적으로 표시
   - 피격 시 **카툰 느낌 데미지 숫자 팝업**(타격감 강화)
7. **이펙트 & 업그레이드 요소**
   - 병력 증가 시 화려한 이펙트 연출
   - 무기 업그레이드 큐브: HP를 깎아 파괴하면 **무기 강화 + 발사체/이펙트 변화**
8. **게임오버/버그 대응 및 안정성**
   - 병력이 0 이하가 되면 즉시 게임오버 처리(불사 버그 방지)
   - 외부 리소스(CORS/로딩 실패) 상황을 대비한 **폴백(대체 렌더링) 구조**

  - DevQ는 에빙하우스 망각곡선 기반의 “짧고 반복 가능한 퀴즈”로 **효율적인 복습 루틴**을 만들고, 실전 면접 상황까지 한 번에 대비하도록 설계했습니다.

### 주요 기능

1. **플래시카드 기반 퀴즈 UI**
   - 질문 확인 → 스스로 답변 구성 → 정답 공개 → “알았어요/몰랐어요” 셀프 평가
2. **데일리 챌린지**
   - 매일 랜덤 5~10문제 제공

3. **카테고리 집중 학습**
   - 운영체제(OS) / 데이터베이스(DB) / 네트워크(Network) / 자료구조(Data Structure) 선택 학습
   - 취약 파트만 빠르게 반복 가능
4. **실전 면접 시뮬레이션(모의면접 모드)**
   - 제한 시간 타이머 제공
   - 주관식/객관식 혼합 형태로 압박감 있는 풀이 흐름 구성
5. **학습 결과 리포트**
   - 세션 종료 시 정답률, “완벽히 앎/복습 필요” 문항 수 요약
   - 홈으로 복귀해 다음 학습으로 연결
6. **문제 은행 기반 확장 구조**
   - 카테고리/문제 데이터가 추가될수록 자연스럽게 확장 가능한 구조(Question Bank 기반)

## 4. 페어 프롬프트 릴레이 앱

### 앱이름 : 알고리즘 코딩테스트 오답노트 학습 플랫폼

### 카테고리 : 페어 프롬프트 릴레이 앱

### 배포링크

https://gemini.google.com/share/bcd6fdd0b8f0

### 이앱을 만든이유

- 어떤 문제/불편함을 해결하려고 했나요?
  - 알고리즘 코딩 테스트를 준비하면서 푼 문제를 체계적으로 복습하지 못해 같은 유형을 반복해서 틀리고, 풀이 후에도 *왜 비효율적인지·어떻게 더 개선할 수 있는지*에 대한 피드백을 받기 어려운 문제를 해결하고자 했습니다. 또한 문제 관리, 복습 일정, 코드 리뷰, 개념 정리를 각각 다른 도구로 나눠 사용해야 하는 번거로움을 하나의 플랫폼으로 통합하고자 했습니다.
- 이 앱을 언제, 어떻게 사용할 건가요?
  - 매일 알고리즘 문제를 풀이한 직후 코드를 등록해 AI 피드백을 받고, 이후 자동으로 생성되는 복습 일정에 따라 다음날·3일 뒤·일주일 뒤·한 달 뒤에 다시 문제를 점검하는 방식으로 사용합니다. 막히는 부분은 ‘알고리즘 선생님’ 챗봇을 통해 즉시 질문하고, 자주 헷갈리는 개념과 코드 스니펫은 요약 정리 기능으로 반복 학습하며 코딩 테스트 준비 전 과정을 일상적으로 관리합니다.

### 주요 기능

1. 문제마다 복습 사이클(다음날, 3일뒤, 일주일뒤, 한달뒤) 자동 제공 및 체크 기능
2. 리팩토링할 부분 찾기
3. 전반적인 피드백 코멘트
4. 더 최적의 방법이 있을 경우 해당 코드 제시
5. 유용한 개념 요약정리
6. 최종 반영 전체 코드

### **AI 기능 (해당되는 경우)**

- 어떤 AI 기능을 추가했나요?
  - 사용자가 입력한 **알고리즘 문제 정보 + 풀이 코드**를 기반으로 **AI 알고리즘 분석·코드 리뷰·복습 설계 기능**을 추가했습니다.
  - 문제 유형 자동 분류 (DFS/BFS, DP, 그리디 등)
  - 시간·공간 복잡도 및 핵심 동작 원리 분석
  - 코드의 **칭찬할 점 / 개선할 점** 분리 리뷰
  - 더 효율적이고 가독성 높은 **최적화 코드 자동 생성**
  - 망각 곡선을 고려한 **개인 맞춤 복습 일정 추천**
  - 분석 깊이를 선택할 수 있는 **분석 강도(간결/보통/세세히) 조절**
- AI 기능이 앱에서 어떤 역할을 하나요?
  - 이 앱에서 AI는 단순한 해설 생성기가 아니라, **개인 알고리즘 코치** 역할을 합니다.
  - 사용자가 문제를 푼 _직후_,
    - 왜 이 풀이가 동작하는지,
    - 어디가 비효율적인지,
    - 실제 코딩 테스트 기준에서 어떻게 개선할 수 있는지를 **사람 리뷰에 가까운 형태로 구조화해 피드백**합니다.
  - 또한 AI가 제안한 **복습 주기(다음날·3일·7일 등)** 를 통해 문제 풀이 → 리뷰 → 재복습이 하나의 흐름으로 이어지도록 도와*“풀고 끝”이 아닌, 실력으로 축적되는 학습 사이클*을 만드는 것이 핵심 역할입니다.

처음 Gemini에게 입력한 프롬프트를 그대로 적어주세요.

```
라스트워- 서바이벌 이라는 게임의 '슈팅게임' 파트를 html 기반 코드로 만들어줘.

먼저 그 게임의 개요, 특성, 등장인물, 디자인, 효과에 대해 상세하게 조사하고 그 내용을 기반으로 어떻게 하면 그 게임과 최대한 비슷하게할수 있을지 알려줘,
```

### 2. 프롬프트 개선 과정

- 처음 결과물의 문제점은 무엇이었나요?
  - 라스트워 “특유의 느낌”이 부족하고, **그래픽/연출이 너무 단순**했음(2D 캔버스 원·사각형 위주).
  - 전장 구성이 실제처럼 **‘중앙 다리’에 집중되지 않고 맵이 넓게** 느껴졌음.
  - 군집이 **원형으로 뭉치는 방식**이 첨부 이미지의 “대형(그리드)” 느낌과 달랐음.
  - 기능이 늘면서 **로딩이 멈추거나(CORS/MIME 문제)** 배경 이미지가 검게 나오는 이슈가 발생.
  - 밸런스가 쉬워서 **긴장감(난이도/보스 빈도/피격 시스템)**이 약했음.
- 어떤 식으로 프롬프트를 수정했나요?
  - **1단계 뼈대 + 이동**부터 분리 요청 (기본 루프/조작 안정화)
  - 핵심 시스템인 **수학 게이트 + 군집 시스템** 구현 요청
  - **디자인 디테일**(머리 위 병사수 표기, 군인 픽토그램) + **밸런스/보스** 추가
  - 총알 궤적, 전장 폭, 지형(바다/다리) 등 **“이미지 기반으로 구체적 요구”** 추가
  - 그래픽 고도화를 위해 **three.js 도입 + 예제 활용을 명시**
  - 군집 형태를 **원형 → 그리드 대형**으로 변경 요청
  - **HP 바 + 데미지 텍스트(Bangers 느낌)** 같은 “피드백 연출” 추가
  - 캐릭터를 실제 3D로: **webgl_animation_multiple(Soldier.glb)** 예제 지정
  - 오디오/보스 주기/특수 적(MD2 Ogre) 등 **콘텐츠 확장**
  - “무한 로딩” 문제 해결을 위해 **CDN 변경/폴백 시스템** 요청
  - “성능” 이슈 해결을 위해 **최대 200명 제한** 요청
  - 시작/스테이지 선택 화면까지 포함해 **메뉴 UX 추가**
  - 마지막으로 **게임오버(사망) 버그 + 배경 이미지 검은 화면** 수정 요
- 몇 번의 반복을 거쳤나요?
  - 대략 **10회 이상 반복**(기능 추가 → 시각/UX → 난이도 → 3D 전환 → 성능/버그 수정 순으로 계속 개선).

### 3. 효과적이었던 프롬프팅 전략

- 어떤 방식으로 요청했을 때 원하는 결과가 나왔나요?
  - **단계를 쪼개서** 요청(“뼈대/이동 → 게이트/군집 → 디자인 → 밸런스 → 3D화 → 최적화/버그”).
  - “라스트워 느낌” 같은 추상 요구 대신,
    - **총알은 직진**
    - **전투는 다리 중앙에서만**
    - **군집은 그리드 대형**
    - **HP는 bar**
    - **데미지 텍스트는 카툰 폰트**
      처럼 **행동/규칙/표현을 구체적으로** 지정했을 때 반영이 잘 됨.
  - three.js는 “멋있게 해줘”가 아니라 **어떤 예제(webgl_animation_multiple, md2_control)를 가져올지**를 찍어줬을 때 훨씬 빠르게 진행됨.
  - 오류 상황에서는 “안돼요”가 아니라 **증상(로딩 화면만 보임, 검은 배경)**을 명확히 말하니 원인(CORS/MIME/드라이브 링크) 추적이 쉬웠음.
- 반대로 효과가 없었던 방식은 무엇이었나요?
  -
  - “라스트워 느낌으로 완전히 바꿔줘”처럼 **목표만 크고 조건이 없는 요청**은 결과가 방향이 흔들렸음.
  - 기능을 한 번에 너무 많이(모델, 사운드, UI, 보스, 무기 업글, 이펙트 등) 넣으면
    - **로딩/CORS/성능** 문제로 실제 실행이 막히고,
    - 디버깅 포인트가 늘어나서 수정 사이클이 길어졌음.

### 4. 배운 점

- Gemini Canvas를 효과적으로 사용하기 위한 나만의 팁이 있다면?
  - 요청 앞에 1,2,3,4 인덱스 붙이기
  - “한 번에 완성” 대신 **작동하는 최소 버전(MVP)**을 먼저 만든 뒤,
    - 기능 추가할 때마다 **즉시 실행 확인 → 다음 단계**로 넘어가기.
  - 요청할 때 “추상적 목표” + “검증 가능한 체크리스트”를 같이 주기
    - 예: “전장 중앙 다리만 이동 가능 / 게이트는 다리 내부만 스폰 / 총알은 직선 / HP bar 보임”처럼.
  - three.js/외부 에셋을 쓰면 **CORS/호스팅 문제**가 자주 생기니,
    - 처음부터 **CDN 후보(예: unpkg/jsdelivr) + 실패 시 폴백(기본 지오메트리)** 전략을 같이 요구하는 게 안정적.

### 5. 리뷰어에게 피드백 받고 싶은 포인트

- “라스트워 슈팅 파트”의 **핵심 재미(게이트 선택 → 성장 → 타격감 → 위험 관리)**가 잘 살아있나요?
- 현재 난이도(적 스폰/보스 빈도/게이트 패널티)가 **너무 쉽거나 어렵지 않은지** 밸런스 피드백이 필요해요.
- 군집 대형(그리드)과 UI(HP bar, 데미지 텍스트)가 **가독성/연출 면에서 과하지 않은지** 평가 부탁해요.
- three.js 적용이 “비슷해 보이는 수준”인지, 더 라스트워스럽게 만들려면
  - **카메라 각도/애니메이션/이펙트/색감** 중 어디를 먼저 손대는 게 효과적인지 조언 받고 싶어요.
