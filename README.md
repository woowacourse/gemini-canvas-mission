## 📝 AI 사용 일지 

### 대상 앱 이름

뇌과학 기반 생산성 플래너 서비스

### 1. 초기 프롬프트

> 처음 Gemini에게 입력한 프롬프트를 그대로 적어주세요.

```
나는 뇌과학에 근거해 최상의 플래너를 짜주는 서비스를 만들고 싶어.
서비스 대상은 오늘 하루를 완벽히 생산적으로 보내고 싶은 사람이야.
개발은 html, css, vanilla js만 사용해.

요구사항은 아래와 같아.

- 첫 화면에서는 오늘 할일들과 나의 평소 생활 루틴을 입력 받는다.
    - 생활 루틴은 평소에 몇시에 자고, 몇시에 일어나는지 입력받는다.
    - 할일들은 글자와 걸리는 시간을 입력받는다.
- 첫 화면 하단에 있는 “가용 시간 입력하기” 버튼을 누르면 일에 사용할 수 있는 시간을 입력받는 페이지로 이동한다.
    - 가용 시간은 30분 단위의 셀들로 표시되며, 각 셀을 선택하면 사용 가능한 시간으로 입력된다.
    - “플래너 만들기” 버튼이 하단에 존재하며, 해당 버튼을 누르면 플래너를 만들기 시작한다.

- 플래너를 만들 때에는 뇌과학에 기초하여 최적의 시간에 최적의 일정을 하도록 넣어주어야 한다. 이는 LLM api를 연동하여 구현한다.
    - 입력된 뇌과학 참고 자료를 바탕으로 사용자가 입력한 평소 생활 루틴에 적용한다.
    - 사용자가 입력한 오늘 할일을 분석하여 적절한 시간에 위치시킨다.
        - 할 일은 동일한 시간에 여러 개가 겹치면 안된다.
        - 얼마나 특정 할 일이 단순 반복인지, 창의적인 사고가 필요한지, 뇌에 피로를 많이 주는지 등을 판단하여 가장 효율적인 시간에 위치시킨다.
- api를 통해 캘린더를 만드는 동안 로딩 화면을 보여준다.

작성된 요구사항을 읽고, 요구사항 재진술, 위험 평가, 단계별 구현 계획을 구상한 이후, 요구사항 분석과 구현사항(TODO), 주의사항을 작성해줘.
```

프롬프트 이후에 Gemini가 작성한 기획 문서를 바탕으로 구현을 요구하였습니다.

```
너는 10년차 프론트앤드 개발자야.
이렇게 작성된 플래너 기획 문서를 바탕으로 구현 단계에 맞추어 실제로 구현해줘
```

### 2. 프롬프트 개선 과정

>- 처음 결과물의 문제점은 무엇이었나요?
>- 어떤 식으로 프롬프트를 수정했나요?
>- 몇 번의 반복을 거쳤나요?

대부분의 요구사항을 충족하는 플래너가 만들어졌지만, 가용 시간 선택 화면에서, 각 셀 이 시간 구간으로 설정되어 있지 않아, 사용자가 가용 시간 선택 시 해당 셀 이 정확히 어떤 시간 구간을 의미하는지 알기 어려웠습니다.

이를 해결하기 위해 아래와 같이 프롬프트를 수정(추가)하였습니다.

```
현재 가용 시간 선택할 때, 각 셀이 구간으로 설정되어있지 않아 사용자가 가용 시간 선택시 해당 셀이 몇시부터 몇시까지인지를 확인하기 어려워.

셀 마다 몇 시부터 몇 시까지를 나타내는지 표시를 변경해줘
```
2번의 반복을 거쳐서 원하는 결과물을 얻을 수 있었습니다.

### 3. 효과적이었던 프롬프팅 전략

>- 어떤 방식으로 요청했을 때 원하는 결과가 나왔나요?
>- 반대로 효과가 없었던 방식은 어떤게 있었나요?

1. 요구사항 분석과 구현 계획 수립을 문서로 작성 후 구현하기

저희가 프리코스 때 했었던, 요구사항을 받으면 이를 분석하고, 구현 계획을 세우고, 각 계획별로 순서대로 구현하는 방식으로 진행했습니다.
이처럼 요구사항을 분석하고, 구현 계획을 세우는 방식이 저에게는 길을 잃지 않고, 요구사항에 충실한 결과물을 얻는데 효과적이었던 것 같습니다.

ai가 주변 컨택스트 지식이 없지만 개발은 할 수 있는, 어쩌면 저희 크루들과 같은 존재라면,
이러한 요구사항을 프롬프트로 입력받았을 때, 위의 프로세스대로 진행할 수 있게 하여 길을 잃지 않고도 요구사항에 충실한 결과물을 얻을 수 있을 것이라 생각하였습니다. 

이에 따라 대부분의 첫 프롬프트에 아래의 문구를 추가하여, 요구사항 분석과 구현 계획을 수립한 문서를 작성하도록 하였습니다.
```
작성된 요구사항을 읽고, 요구사항 재진술, 위험 평가, 단계별 구현 계획을 구상한 이후, 요구사항 분석과 구현사항(TODO), 주의사항을 작성해줘.
```

이후 작성된 기획 문서를 바탕으로 구현하도록 하였습니다.
특히나 Gemini는 작성된 문서를 바탕으로 "구현하기" 버튼이 존재하므로, 이 프로세스가 자연스럽게 이어질 수 있었습니다.

실제로 결과물은 요구사항에 대부분 충실하였습니다. 

2. 구체적인 요구사항 제시하기

1번의 방식을 통해 요구사항을 만족하는 결과물은 쉽게 얻을 수 있었습니다. 하지만 처음에는 요구사항이 구체적이지 않아서, 바로 원하는 결과물이 나오지 않았습니다.
예를 들어, 처음에는 가용 시간 선택 화면에서 각 셀 이 시간 구간으로 설정되어 있지 않아, 사용자가 가용 시간 선택 시 해당 셀 이 정확히 어떤 시간 구간을 의미하는지 알기 어려웠습니다.
해당 부분을 정확하게 각 셀 별로 어떻게 시간이 표시되어야 하는지를 설명하지 않았기 때문이었습니다.
이를 통해서 얼마나 구체적으로 요구사항을 제시하느냐가 원하는 결과물을 얻는데 중요한 역할을 한다는 것을 알 수 있었습니다.

앞으로 점점 ai가 발전함에 따라 ai 활용 능력이 중요해지고, 필수 역량이 되어가고 있는데,앞으로 얼마나 본인이 머릿속에 떠올리고 있는 것을 자연어로(말로, 글로) 구체적이고 정확하게 설명할 수 있는지가 ai 혹은 사람과 협업하는데 핵심이 될 것이라고 생각하였습니다.

### 4. 배운 점

>Gemini Canvas를 효과적으로 사용하기 위한 나만의 팁이 있다면?

ai는 코딩 능력을 가졌지만, 길을 잘 잃어버리는 사람이라고 생각합니다.
따라서 ai에게 요구사항을 제시할 때에는, ai가 길을 잃지 않고, 요구사항에 충실한 결과물을 낼 수 있도록, 요구사항 분석과 구현 계획을 세우는 문서를 작성하도록 하는 것이 효과적이었던 것 같습니다.

또한 요구사항을 제시할 때에는 실제로 우테코에서 요구사항 문서를 작성하듯 구체적이고 명확하게 작성하는 것이 원하는 결과물을 얻는데 중요한 역할을 한다고 생각합니다.

### 5. 리뷰어에게 피드백 받고 싶은 포인트

아직은 요구사항을 제시하는 방식에 대해서 익숙하지 않는 것 같습니다. 
리뷰어분께서는 ai에게 요구사항을 제시할 때, 어떤 방식으로 제시를 하시는지 그 팁과, 지금까지 좋은 요구사항 문서를 작성하기 위하여 했던 의식적인 노력들이 있다면 공유해주시면 감사하겠습니다.
