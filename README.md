# 앱 이름: 행성 수박 게임
## **카테고리: 게임**

## **배포 링크**

- https://gemini.google.com/share/820d843e27ea


### **이 앱을 만든 이유**
#### **어떤 문제/불편함을 해결하려고 했나요?**

기존의 수박게임은 빠르게 진행하는 것이 쉽지 않다고 느꼈습니다.

그래서 게임 흐름을 보다 속도감 있게 구성하고, 블랙홀 아이템을 통해 잘못 쌓인 상황을 전략적으로 해결할 수 있도록 기획하였습니다.

또한 귀여운 2D 행성 디자인과 물리 엔진 기반의 자연스러운 움직임을 더해 시각적인 재미와 몰입감을 동시에 제공하는 것을 목표로 했습니다.

<br/>  

#### **이 앱을 언제, 어떻게 사용할 건가요?**
- 쉬는 시간이나 대중교통 이동 중처럼 **짧은 시간 동안 가볍게 즐기고 싶을 때** 사용합니다.
- 점수를 갱신하며 기록에 도전하는 **캐주얼 랭킹형 게임**으로 활용할 수 있습니다.
- 모바일 환경에서도 터치로 간편하게 플레이할 수 있도록 제작되었습니다.


### **주요 기능**

- 행성을 떨어뜨리면 물리 엔진 기반으로 아래에서부터 차곡차곡 쌓입니다.
- 같은 단계의 행성이 서로 만나면, 한 단계 더 큰 행성으로 진화합니다.
- 가장 큰 단계는 태양이며, 점점 더 거대한 행성으로 합성할 수 있습니다.
- 쌓인 행성이 일정 높이(데드라인)를 넘으면 게임이 종료됩니다.
- 다음에 등장할 행성을 미리 확인할 수 있어 전략적인 플레이가 가능합니다.
- 위기 상황에서 사용할 수 있는 **블랙홀 아이템**으로 주변 행성을 제거할 수 있습니다.
- 현재 점수와 최종 점수를 확인할 수 있으며, 재시작 기능을 제공합니다.

# 앱 이름: Python 2 Java

## **카테고리: 개발 학습 도구 (코딩테스트 지원 앱)**

### **배포 링크**

- https://gemini.google.com/share/ef42f20a5025


### **이 앱을 만든 이유**

#### **어떤 문제/불편함을 해결하려고 했나요?**

코딩테스트를 파이썬으로 준비하던 개발자들이 자바(Java)로 전향할 때 다음과 같은 어려움이 있습니다.

- 문법 차이로 인해 같은 로직을 자바로 어떻게 작성해야 할지 막막하다
- 빠른 입출력(BufferedReader, StringTokenizer 등)에 대한 부담된다.
- 단순 코드 변환이 아닌, **문법 차이를 이해하며 학습하고 싶다.**

기존의 단순 코드 변환기는 “번역”만 제공할 뿐, **왜 이렇게 바뀌는지에 대한 설명과 코딩테스트 관점의 최적화 가이드가 부족했습니다.**


<br/>  


#### **이 앱을 언제, 어떻게 사용할 건가요?**

- 파이썬으로 작성한 코드를 자바로 바꿔보고 싶을 때 이해를 깊게 하고 싶을 때 사용합니다.
- 즉, **“파이썬 코테 → 자바 코테 전향자”를 위한 학습 보조 도구**로 활용됩니다.



### **주요 기능**

- 파이썬 코드를 입력하면 코딩테스트 제출용 자바 코드로 자동 변환
- 클래스명을 Main으로 고정하여 실전 제출 환경에 맞게 생성
- BufferedReader, StringTokenizer 기반의 빠른 입출력 자동 적용
- 파이썬 ↔ 자바 문법 차이 비교 카드 형태로 제공
    - 리스트/배열 차이
    - 반복문 차이
    - 입력 처리 방식 차이
    - 정렬, 자료구조 사용법 차이 등
- 자바 코딩테스트 준비자를 위한 실전 팁 제공
- 로딩 UI 및 에러 처리 지원
- JSON 스키마 기반 구조화된 응답 처리로 안정적인 렌더링

---

### **AI 기능**

- Gemini API를 활용하여 파이썬 코드를 분석하고 자바 코드로 변환
- 단순 변환이 아닌, 구조화된 JSON 응답 생성
    - javaCode : 제출 가능한 완전한 자바 코드
    - differences : 문법 비교 및 설명
    - tips : 자바 코테 학습 팁

금지하거나 제한할 구현 조건 : 프롬프트에 코드에 대한 내용을 절대 작성하지 않는다.

## 2. 프롬프트 개선 과정

- 처음 결과물의 문제점은 무엇이었나요?

- 어떤 식으로 프롬프트를 수정했나요?
    - 추가할 기능을 하나씩 덧붙여 나가고 수정해 나가는 방식으로 진행했습니다.
    - 어느정도 진전이되면, 이때까지 했던 구성물에 대해서, 어떤 식으로 프롬프트를 작성하면 이러한 결과물이 나올 수 있는지 질문을 하였습니다.
    - 나왔던 프롬프트를 새 창에 다시 입력하고, 이 결과물에 대해서 다시 초기 프롬프트로 구성해서 시작하였습니다.

- 몇 번의 반복을 거쳤나요?
    - 위의 사이클을 3번 반복하였습니다.
