# gemini-canvas-mission

Gemini Canvas 미션 결과물을 관리하는 저장소입니다.

## 목적

- Gemini Canvas로 제작한 웹앱 결과물을 기록하고 공유합니다.
- 앱별 요구사항, 배포 링크, 회고를 일관된 형식으로 남깁니다.

### 1. 초기 프롬프트
처음 Gemini에게 입력한 프롬프트를 그대로 적어주세요.
```
HTML, CSS, JavaScript만 사용해서 만들어줘.
React나 다른 프레임워크는 사용하지 마.
너는 이제 '벨튀 게임'을 만들거야.
플레이어는 벨튀를 당하는 사람이야.
총 3턴을 진행할거고, 아이 세명이 벨을 누르고 도망을 갈거야.
이때 아이는 달리기속도가 1~7중에 랜덤이야.
그리고 플레이어는 각 턴마다 달리기 속도를 고를 수 있는데, 3턴의 합이 15 이하 여야해.
그리고 각 턴마다 내가 아이의 달리기 속도보다 빠르거나 같으면 그 아이는 잡은거야.
3턴이 끝나고 6명 이상의 아이를 잡으면 나는 '최고의 홈프로텍터' 칭호를 가지게되고, 
3명 이상 6명 미만이면 '그저그런 홈프로텍터', 3명 미만이면 '그냥 사람' 칭호를 가지게 돼.
3턴이 끝나고 그 칭호를 띄워주면서 게임은 마무리되면돼.
앱 시나리오를 다시 정리해주자면
1. 플레이어 닉네임을 입력받는다.
2. 첫번째 턴, 달리기속도를 입력받는다.
3. 아이들이 벨튀를 하고 내가 붙잡은 아이 수를 보여준다. 그리고 아이들이 뛰어가고 플레이어가 붙잡는 애니메이션도 있으면 좋겠어.
4. 두번째 세번째 턴도 2번과 3번의 반복이다.
5. 마지막에 내가 붙잡은 아이들의 수와 칭호를 제시한다.
```

### 2. 프롬프트 개선 과정
- 처음 결과물의 문제점은 무엇이었나요?
    - 디자인이 생각과 정말 많이 달랐고, 캐릭터의 달리기 속도가 너무 느리기도 해서 제가 생각한 게임 진행과 달랐습니다.
- 어떤 식으로 프롬프트를 수정했나요?
    - 로직이 잘못된 점을 말하고, 이후에는 디자인적 요소를 요구했습니다.
    - 로직이나 디자인의 수정이 잘 이루어지지 않으면 다른 AI 모델에게 코드를 제시 후 동작이 되지 않는 지점을 고쳐달라고 요구했습니다. 이때 고쳐준 부분을 가지고 와서 canvas에게 반영해달라고 요구했습니다.
- 몇 번의 반복을 거쳤나요?
    - 53번

### 3. 효과적이었던 프롬프팅 전략
- 어떤 방식으로 요청했을 때 원하는 결과가 나왔나요?
    - 수정이 잘 이루어지지 않으면 canvas를 끄고 제미나이나 gpt에게 로직의 잘못된 점을 알려달라고 했습니다. 수정된 부분을 다시 canvas에게 가지고 가서 이를 반영해달라고 요구하면 원하는 결과에 가까워졌습니다.
- 반대로 효과가 없었던 방식은 무엇이었나요?
    - 추상적으로 말하는 것이 효과가 없었습니다.(ex. 스위스풍 집이면 좋겠어!)

### 4. 배운 점
- Gemini Canvas를 효과적으로 사용하기 위한 나만의 팁이 있다면?
    - 처음부터 너무 많은 것을 요구하면 더욱 수정하기 어려워지는 것 같습니다. 처음부터 모든 기능을 구현하려 하지 않고, 페이지별로 요구하는게 효과적인 것 같습니다. 첫번째 페이지가 어느정도 완성되면 그 이후 흐름을 구현해달라고 요구하니 훨씬 더 수정 속도가 빨랐습니다. 또한 다른 llm을 로직 수정에 이용하는 것도 편했습니다.

### 5. 리뷰어에게 피드백 받고 싶은 포인트
- 효과적인 프롬프트는 어떻게 작성하면 될까요? 웹앱을 기획하고 개발하는 것 뿐만 아니라 앞으로 코드를 작성할 때에도 효과적으로 사용하려면 어떻게 해야하는지 궁금합니다.
