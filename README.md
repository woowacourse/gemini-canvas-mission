- 본인이 이 앱을 언제, 어떻게 사용할 건가요?




### 대상 앱 이름
`행성이의 리듬 어드벤처`

### 1. 초기 프롬프트

```text
웹 기반 리듬 게임을 제작해줘. 게임의 이름은 행성이의 리듬 어드벤처이며, 다음의 상세 가이드라인을 따라 HTML5 Canvas와 Vanilla JavaScript로 코드를 작성해줘.

1. 게임 컨셉 및 물리 엔진

게임 방식은 수평으로 달리는 러너 게임이며, 화면 중앙의 수평선을 기준으로 위아래 두 개의 레인이 존재한다.
플레이어 캐릭터인 행성이는 위아래 방향키를 사용하여 레인을 즉시 이동한다.
장애물은 음악의 박자에 맞춰 위와 아래 레인에 번갈아 가며 나타난다.
장애물에 한 번이라도 부딪히면 게임은 즉시 처음부터 다시 시작된다.

2. 비주얼 및 애니메이션 효과

캐릭터 이미지는 내가 첨부한 PNG 파일을 사용해줘. 이미지는 시계방향으로 45도 회전시킨 것이 정방향이야. 그것을 기준으로 수평선 아래로는 수평방향으로 반전시켜야해.
레인을 변경할 때 화면이 아주 미세하게 확대(Scale)되었다가 돌아오는 효과를 넣어줘.
배경색은 리듬의 강세나 레인 변경 시점에 맞춰 점멸하거나 색상이 변하는 효과를 추가해줘.
Canvas의 requestAnimationFrame을 사용하여 60fps의 부드러운 움직임을 구현해줘.
우아한 테크코스 행성이 이미지를 사용하므로 배경을 포함해서 전체적인 게임은 우주 컨셉이어야해.

3. Web Audio API 및 사운드 로직

음악 파일(mp3 등)을 사용하지 않고 오직 Web Audio API의 OscillatorNode와 GainNode 등을 사용하여 사운드를 직접 생성해줘.
인터넷에서 공개된 8비트 게임 음악(예: 젤다의 전설 테마 또는 클래식 명곡의 8비트 버전) 중 리듬 게임에 적합하도록 정교하게 짜인 JSON 형태의 악보 데이터를 포함해줘.
이 악보 데이터의 박자(Time)와 음높이(Frequency) 정보에 따라 장애물이 정확한 타이밍에 생성되도록 연동해줘.

4. 코드 구조 요구사항

모든 코드는 하나의 HTML 파일 안에 HTML, CSS, JavaScript가 포함된 형태로 작성해줘.
함수는 게임 루프(update, draw), 사운드 엔진(playNote), 입력 처리(handleInput), 충돌 판정(checkCollision)으로 명확히 구분해줘.
나중에 내가 이미지를 교체하기 쉽도록 캐릭터 렌더링 부분은 주석으로 상세히 설명해줘.
```

### 2. 프롬프트 개선 과정

#### 1. 처음 결과물의 문제점

- **단조로움**

`초기 음악이 너무 단순했고, 박자마다 장애물이 정직하게 나와 리듬 게임 특유의 긴장감이 부족했습니다.`

- **난이도 고정**

`시간이 지나도 속도가 그대로여서 게임이 너무 쉬웠습니다.`

- **이미지 렌더링 한계**

`로컬 이미지 파일을 웹 캔버스 환경에서 직접 불러올 때 보안(CORS) 및 경로 문제가 발생하여 캐릭터가 단순한 도형으로 대체되어 출력되었습니다.`

### 2. 프롬프트 수정 방식

원하는 게임의 형태를 구체적인 비유를 통해 구체적으로 개선했습니다.

- **사운드 및 패턴 개선**

`"풍부한 명작 음악 소스를 사용해달라", "특정 강세에만 장애물이 나오게 해달라"고 요청하여 테트리스 테마(화음 포함)와 개선된 패턴이 등장하도록 했습니다.`

- **동적 난이도 도입**

`"크롬 공룡 게임처럼 갈수록 빨라지게 해달라", "3초마다 점점 더 빠르게 해달라"며 구체적인 가속 주기와 레퍼런스를 제시해 난이도를 높였습니다.`

- **랜덤성과 밸런스 조절**

`"장애물이 무작위로 빈번하게 나오게 하되, 피할 수 없는 구조가 나오지 않게 최소 간격을 보장해달라"고 디테일한 생성 규칙을 정했습니다.`

- **이미지 첨부 제약**

`이미지 URL 연동 방식이 실패하여, "코드로 직접 러너 모양을 표현해달라"고 프롬프트를 전환하여 외부 파일 의존성을 없애고 자체 애니메이션 캐릭터를 얻어냈습니다.`

#### 2. 프롬프트 반복 횟수

초기 프로토타입 생성 이후, 총 6번의 프롬프트 수정을 거쳤습니다.

```text
[음악 풍부화] -> [난이도 가속] -> [이미지 URL 적용] -> [3초 단위 극한 가속] -> [무작위 장애물 패턴] -> [자체 캔버스 드로잉 전환]
```

#### 3. 효과적이었던 프롬프팅 전략

`효과적인 프롬프팅`

- 구체적인 수치와 레퍼런스 제시

```text
"3초마다 점점 빨라지도록 만들어줘", "제목과 안내를 위로 올려서 서로 겹치지 않게 해줘"처럼 명확한 수치나 위치를 제시했을 때 의도한 대로 즉시 구현되었습니다.

"크롬의 인터넷 없음 때 게임처럼"이라는 비유를 통해 점진적 가속이라는 기획 의도를 단숨에 이해시킬 수 있었습니다.
```

- 예외 조건 설정

```text
"이상한 장애물 구조가 나오지 않게, 최소 간격은 존재하도록 해줘"라고 게임 플레이의 마지노선을 설정해주었을 때, 플레이 가능한 수준의 난이도를 구성해냈습니다.
```

### 4. 배운 점

- Gemini Canvas를 효과적으로 사용하기 위한 나만의 팁이 있다면?

```text
우테코 문서에 작성된 프롬프트 팁처럼 요구사항이 구체적일 수록 문제점이 확실하게 개선되는 것을 느꼈습니다.

결국 프롬프트를 얼마나 구체적이고 정확하게 작성하냐에 따라서 AI의 결과물은 천차만별이 될 수 있는 것 같았습니다.

또한, 게임에 이미지를 첨부하려는 시도를 통해 알게된 것은 내가 만들고자 하는 것에 대해 정확하게 알지 못한다면 원하는 결과물을 만드는데 걸림돌이 될 수 있다는 것이었습니다.

잘 모르는 분야들에 대해 수준급의 결과물을 만들어낼 수 있다는 것이 AI의 정점이면서도, 분야들에 대해 잘 알지 못하면 근본적인 문제점을 해결하지 못한 채 프롬프팅만 반복되는 상황이 발생할 수 있다는 것이 딜레마였습니다. 
```
