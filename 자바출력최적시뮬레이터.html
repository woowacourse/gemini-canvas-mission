Java 출력 최적화 시뮬레이터

System.out.println() vs StringBuilder 성능 차이 시각화

System.out.println()
Application Memory
↓
System I/O Call (Heavy!)
↓
Standard Output (Console)
시스템 호출 0
상대적 시간 0ms
StringBuilder
StringBuilder (Memory Buffer)
↓
Single Batch I/O Call
↓
Standard Output (Console)
시스템 호출 0
상대적 시간 0ms
// [비교 코드 예시]

// 1. System.out.println (느림)
for(int i=0; i<N; i++) {
    System.out.println("Data line " + i);
}

// 2. StringBuilder (빠름)
StringBuilder sb = new StringBuilder();
for(int i=0; i<N; i++) {
    sb.append("Data line ").append(i).append("\n");
}
System.out.print(sb.toString());

왜 StringBuilder가 더 빠른가요?

System.out.println()은 호출될 때마다 애플리케이션에서 운영체제의 커널 영역으로 시스템 호출(System Call)을 보냅니다. 이 과정은 '컨텍스트 스위칭'을 유발하며, 실제 입출력 장치와 동기화 작업을 수행하기 때문에 매우 비싼 비용이 발생합니다.

반면 StringBuilder는 모든 문자열을 메모리 내부의 char[] 배열에 단순히 추가합니다. 메모리 작업은 시스템 호출에 비해 수천 배 빠릅니다. 마지막에 단 한 번의 출력 호출만 수행함으로써 입출력 부하를 극적으로 줄일 수 있습니다.

* 알고리즘 문제 풀이(PS) 환경에서는 수만 줄의 출력이 발생하므로, 이 차이가 '시간 초과' 여부를 결정짓기도 합니다.
