## 카테고리: 학습 앱

### 배포 링크

### 이 앱을 만든 이유

- 어떤 문제/불편함을 해결하려고 했나요?  
개발 지식(프론트엔드, 백엔드, 안드로이드)을 공부할 때, 단순히 텍스트를 읽는 것만으로는 내 실력을 객관적으로 점검하기 어렵습니다. 또한 퀴즈를 풀다 틀렸을 때 기본 해설만으로는 완벽히 이해되지 않는 경우가 많은데, 이때 즉각적으로 질문하고 답변을 받을 수 있는 '1:1 튜터'의 부재라는 불편함을 해결하고자 했습니다.

- 이 앱을 언제, 어떻게 사용할 건가요?  
개발자 기술 면접을 앞두고 기초부터 심화 지식까지 빠르게 점검하고 싶을 때, 혹은 출퇴근길 등 자투리 시간에 가볍게 퀴즈를 풀며 본인의 학습 상태를 확인하고 복습하는 용도로 사용합니다.

### 주요 기능

- 맞춤형 퀴즈 생성:  
  프론트엔드, 백엔드, 안드로이드의 3가지 카테고리와 기본/중급/고급 난이도, 원하는 문제 수(1, 5, 10문제)를 조합하여 나만의 테스트를 세팅할 수 있습니다. (총 90개의 엄선된 문제 내장)

- 즉각적인 오답 피드백:  
  오답을 선택하면 즉시 진행을 멈추고 팝업창을 통해 '정답'과 '상세한 해설'을 제공하여, 틀린 즉시 올바른 개념을 학습할 수 있도록 돕습니다.

- 최고 점수 및 동기 부여 시스템:  
  브라우저 로컬 스토리지를 활용하여 사용자의 역대 최고 점수를 기록하고, 점수대별로 맞춤형 동기 부여 메시지를 제공합니다.

- 누적 오답 노트 저장소:  
  틀렸던 문제와 해설은 '누적 오답 노트'에 자동으로 저장되어, 메인 화면에서 언제든지 나의 취약점을 다시 열람하고 복습할 수 있습니다.

### AI 기능

- 어떤 AI 기능을 추가했나요?  
오답 노트 시스템과 완벽하게 통합된 'AI 튜터 Gemini 인앱 챗봇' 기능을 구현했습니다.

- AI 기능이 앱에서 어떤 역할을 하나요?  
사용자가 제공된 기본 해설만으로 개념이 헷갈릴 때, 오답 노트의 Gemini에게 더 물어보기 버튼을 클릭하면 즉시 인앱 채팅창이 열립니다. 틀린 문제와 정답에 대한 컨텍스트가 챗봇 시스템 프롬프트에 자동으로 전달되며, 사용자는 앱을 이탈하지 않고 시니어 개발자 페르소나를 가진 AI와 실시간으로 대화하며 꼬리 질문을 던지고 심층적인 학습을 이어갈 수 있습니다.

## AI 사용 일지

### 1. 초기 프롬프트
```
[역할 부여 및 개발 조건]

Gemini, 너는 탁월한 UI/UX 기획자이자 웹 프론트엔드 시니어 개발자야. 아래의 기획안을 바탕으로 브라우저에서 바로 실행할 수 있는 웹 기반 퀴즈 앱을 만들어 줘.

필수 조건: 반드시 HTML, CSS, JavaScript(Vanilla JS)만 사용해서 작성해 줘. React, Vue 등 다른 프레임워크나 외부 라이브러리는 절대 사용하지 마.

코드 테스트가 편하도록 index.html 파일 하나 안에 <style>과 <script>를 모두 포함해서 작성해 줘.



[앱 서비스 개요]

서비스 목적: 프론트엔드, 백엔드, 안드로이드 개발 지식을 퀴즈를 통해 학습하고, 오답 시 즉각적인 해설을 제공하는 학습 앱.

주요 특징: 맞춤형 문제 설정, 즉각적인 오답 피드백, 로컬 스토리지를 활용한 최고 점수 기록(동기 부여), 심화 학습 유도.



[핵심 유저 플로우 및 기능 명세]

1. 초기 설정 화면

카테고리 선택 (Select box 또는 버튼): 프론트엔드, 백엔드, 안드로이드

난이도 선택 (Select box 또는 버튼): 기본, 중급, 고급

문제 수 설정 (Select box 또는 버튼): 1문제, 5문제, 10문제

'퀴즈 시작' 버튼

2. 문제 풀이 화면

문제 타이틀, 4지 선다형 보기 버튼 제공.

정답 클릭 시: "정답입니다!" 메시지와 함께 매끄럽게 다음 문제로 이동.

오답 클릭 시: 진행을 멈추고 팝업이나 알림창으로 즉시 **'정답'과 '상세한 해설(왜 오답인지)'**을 제공. 유저가 '확인'을 누르면 다음 문제로 이동.

참고: 앱이 바로 동작하는지 테스트할 수 있도록, 각 카테고리/난이도별로 2~3개씩 하드코딩된 더미 퀴즈 데이터를 JavaScript 배열 안에 미리 넣어 줘.

3. 결과 및 동기 부여 화면

모든 문제를 풀면 총 맞춘 개수와 최종 점수(예: 100점 만점 기준)를 화면에 표시.

브라우저의 localStorage를 사용해 유저의 **'이전 최고 점수'**를 저장하고 불러와 화면에 함께 표시해 줘. (예: "현재 점수: 80점 / 나의 최고 점수: 100점 -> 다음엔 더 잘해봐요!")

오답 노트: 이번 테스트에서 틀린 문제와 해설을 목록으로 보여줘.

AI 심화 학습 연동: 오답 노트의 각 문제 옆에 "Gemini에게 더 물어보기" 버튼을 만들어 줘. 이 버튼을 누르면 "이 문제(문제 내용)의 정답이 (정답 내용)인 이유를 더 자세히 설명해 줘" 라는 텍스트가 클립보드에 자동 복사되고, "질문이 복사되었습니다. Gemini에게 붙여넣기 해보세요!"라는 알림이 뜨게 해 줘.

[요청 사항]

위의 기획과 흐름이 완벽하게 동작하는 세련되고 깔끔한 디자인의 코드를 작성해 줘.
```

### 2. 프롬프트 개선 과정
처음 결과물의 문제점은 무엇이었나요?

1. 데이터 출력 오류:   
  각 난이도마다 5문제를 선택하고 퀴즈를 시작했는데, 2문제만 나오는 현상이 있었습니다.
2. UX의 불편함:   
  오답에 대해 추가 질문을 하려면 질문이 클립보드에 복사된 후 별도로 Gemini에 접속해야 했습니다. 이를 앱 내에서 챗봇 형식으로 바로 대화할 수 있도록 개선이 필요했습니다.
3. 기능 누락:   
  오답 노트를 따로 모아두는 공간이 기획에 있었으나 구현되지 않았습니다.

- 어떤 식으로 프롬프트를 수정했나요?   
"지금 코드를 보니 초급/중급/고급 문항 수가 부족한데, 각각 10문제씩 꽉 채워줘. 그리고 지금은 내가 직접 외부 Gemini로 들어가서 질문을 해야 하는 구조인데, 챗봇 형식으로 앱 내에서 바로 질문할 수 있도록 만들어 주면 좋겠어. (이때 챗봇은 시니어 개발자 페르소나를 가진 AI로 설정해 줘.) 마지막으로 오답 노트를 따로 모아두는 곳이 없는데 추가로 구현해 줘."

- 몇 번의 반복을 거쳤나요?   
총 4번의 프롬프트 수정과 반복 과정을 거쳐 완성했습니다.

### 3. 효과적이었던 프롬프팅 전략
- 원하는 결과가 나온 요청 방식:   
제가 원하는 기능의 요구사항을 추상적으로 묘사하기보다는, 구체적인 기능 명세와 동작 방식을 상세히 설명했을 때 의도에 가장 가까운 결과물이 도출되었습니다.

- 효과가 없었던 요청 방식:   
단순히 "내가 원하는 기능이 없으니 추가해 줘"라고 무작정 지시하는 방식은 효과가 없었습니다. 문제가 발생한 위치나 구체적인 맥락(어디서, 어떻게 누락되었는지)을 함께 설명해야 AI가 엉뚱한 코드를 건드리지 않는다는 것을 알게 되었습니다.

### 4. 배운 점
- Gemini를 효과적으로 사용하기 위한 나만의 팁:   
먼저 제가 원하는 기능과 디자인을 브레인스토밍하듯 쭉 적어봅니다. 그다음 본격적인 개발 프롬프트를 작성하기 전에, Gemini에게 "내가 이런 앱을 만들려고 하는데, 네가 코드를 잘 짤 수 있도록 내 아이디어를 효과적인 프롬프트로 다듬어 줘" 라고 1차 요청을 합니다. AI가 이해하기 쉬운 구조로 변환해 준 프롬프트를 바탕으로 제 의도에 맞게 조금 더 수정을 거쳐 사용하면, 훨씬 더 높은 퀄리티의 결과물을 얻을 수 있습니다.

### 5. 리뷰어에게 피드백 받고 싶은 포인트
- 코드 스파게티화 방지 노하우:   
  AI를 활용해 개발할 때, 오류를 하나 해결하면 다른 곳에서 새로운 오류가 발생하는 이른바 '핑퐁'을 겪다 보니 코드가 스파게티처럼 복잡해지는 경우가 있었습니다. 기존 코드 구조를 망가뜨리지 않으면서 내가 원하는 부분만 딱 고치도록 유도하는 프롬프팅 팁이나 개발 접근법이 있을지 궁금합니다.

- 초기 프롬프트 최적화:   
  이번 온보딩 미션은 상대적으로 복잡도가 낮았음에도 불구하고 원하는 결과를 얻기까지 4번의 반복 과정을 거쳤습니다. 반복 횟수를 더 줄이고, 한 번에 정답에 가까운 코드를 얻기 위한 초기 프롬프트 설계 노하우가 있다면 조언을 듣고 싶습니다.
